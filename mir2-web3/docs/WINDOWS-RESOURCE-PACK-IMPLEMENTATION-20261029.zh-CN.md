# Windows 资源包更新实现与验收

本记录对应 Windows 更新架构改造，源码已推送到 `codex/windows-player-journey`：

- `ba79cc90b47fa2fe017f977c29ea2c987342bcfe`：资源包格式、运行时读取、受签 generation、兼容引擎桥和发布工具。
- `29a187a272acb4129e3de2cd37e6bbdf62bf11e3`：正确处理 Cargo 自然产生的链接输出，复制为单链接发布文件后核验，保留构建缓存。

设计与五分钟验收口径见[架构说明](WINDOWS-RESOURCE-PACK-ARCHITECTURE-20261029.zh-CN.md)。本记录不代表五分钟性能或人工前端 Accepted 已通过。

## 已实现的行为

游戏资源由不可变包和受摘要绑定的目录索引提供，Windows 游戏直接读取包。更新时下载缺少的包并校验，完成后原子切换 generation，不再将全部资源解压并逐个覆盖到旧游戏目录。

签名清单绑定代码、配置、目录索引、资源包及引擎来源。待确认版本必须由实际游戏通过内核 PID 和本轮随机标识报告登录界面就绪，并继续存活至少十秒，才会成为健康版本。失败保留原版本和用户文件，最高发布序号不会随本地健康回滚降低。

历史启动器入口保留。根频道的桥 29 保留原 R25 游戏，五职业频道的桥 30 保留 Candidate28 游戏；新引擎再发现独立资源包频道的 31 版。首次迁移需要旧桥流程和关闭、重开，不能用普通资源包更新成绩代替迁移成绩。

## 已取得的实际证据

新 Windows 游戏来自干净源码 `29a187a`，发布 EXE 为 115,909,632 bytes，SHA256 为 `F3B0E756A2DF5747EFB0D2A3613E2FADD4687D982CF8CF280EA99BF0654AA25C`。构建前后实际检查 1,302 个 Rust/Cargo 源文件，源码未变化；本次使用缓存构建，不声称可复现或 hermetic 构建。

全部 255,057 个原逻辑资源保留，逐路径 size/SHA 与原严格清单一致，并由实际 PackStore 完整读取核验。去重后形成 33 个包，共 1,069,012,997 bytes；目录索引为 68,664,916 bytes。31 版完整必需内容为 1,253,598,488 bytes。资源来源仍是 Candidate28 的 `33f0b8c`，与新 EXE 的源码来源分别记录。

完整受签目标已通过实际本地文件源安装和实际游戏启动。登录界面约 5.75 秒就绪，启动约 25.56 秒后完成健康确认；原界面选择的俄语偏好保留，游戏之后正常退出，退出码为零。该过程不包含网络下载，不能作为五分钟公网更新成绩，也没有代替手机钱包签名或人工建角验收。

测试服已部署 31 版静态内容，源站 137 项 HTTP 检查通过，包括 HEAD、条件请求、Range、清单别名和拒绝路径。原根频道 23 与五职业频道 24 在该检查时字节保持一致。部署仅重新加载 Caddy，游戏网关和钱包服务进程保持原 PID，没有执行数据库修改或启动 Docker。

清理临时发布设施后，再用原始 `7404…` 启动器在已健康安装完整资源包的隔离目录中进行联网启动。实际进程链为原启动器、`343C…` 引擎和 `F3B0…` 游戏；签名版本发现成功，packed-update 阶段用时 28,744 ms，响应体 10,598 bytes，新增包数为零，没有重新激活。实际俄语登录页与 Dubhe Wallet 入口可见，之后正常请求关闭并确认三个测试进程均已退出。这是已有包的联网功能验证，不能充当 C824 冷迁移、首次下载或五分钟成绩。

完整 R2/CDN 发布准入未通过：两次 SSH 传输中断保留失败回执，最后单通道校验也以远端 HTTP 结果未知结束，仅完成 6/40 个正式 stage 对象校验。没有提升 R2 packed latest，也没有提升两个旧桥。已删除临时发布 Worker、路由、临时 BIC 例外及本机临时凭据，保留正式只读资源路由和规则。

最终九项投送状态检查全部符合预期：旧根频道和五职业频道的清单、签名字节及 no-store 保持不变；源站候选版仍为 31；未发布的 R2 packed 别名按只读 Worker 的约定返回 `503 delivery_unavailable`，不可被记作已发布。最初收尾检查误将该状态预期为 404，错误检查回执保留，已按提交的 Worker 实现纠正检查口径。最后再次确认三个后端 PID 与修改前一致。

## 网络与待完成验收

本机直连 CDN 的一次有界 1 MiB Range 探测在 18 秒内仅收到 475,136 bytes；源站在约 8.24 秒取得完整 1 MiB。服务器到同一 CDN 的相同 Range 约 0.63 秒完成。收到的部分内容与已签核索引前缀一致。小 Range 成绩不能外推完整吞吐；它已经说明本机本次路径不足以证明持续有效吞吐至少 60 Mbps 的验收档。

完整 CDN 发布校验使用单独标注的服务器执行位置，核验实际全部对象 SHA 和字节数；该校验不能代表玩家网络速度。旧启动器冷迁移、关闭重开在内的完整墙钟、普通增量发布、故障与完整旧版回滚仍须分别保留实测结果。未通过的项目保持未通过，不能仅凭资源包安装快便宣称整体五分钟达标。

首次完整下载在 60 Mbps 有效载荷吞吐下的传输物理下限约为 167.15 秒，仍须加上发现、校验、持久化、切换和健康启动。当前实际网络低于该条件时，剩余工作是改善分发链路和减少必须下载的新增字节，不能用取消哈希或略过健康确认换取表面进度。

## 大陆与海外同时覆盖

用户已明确要求同时覆盖大陆和海外，并确认目前没有国内 CDN 账号及已备案下载域名。当前源代码中没有找到已接入的阿里云、腾讯云等下载镜像。不能据此声称大陆节点已接通，也没有开通新的 CDN 付费套餐或修改 DNS。

海外保留 Cloudflare/R2；大陆需要可实测的独立分发线路。Cloudflare 普通全球网络将大陆流量交由境外节点处理，China Network 属于单独服务；其接入条件见 [Cloudflare 路由说明](https://developers.cloudflare.com/support/troubleshooting/general-troubleshooting/geographic-traffic-routing/)和 [China Network 接入说明](https://developers.cloudflare.com/china-network/get-started/)。阿里云、腾讯云的大陆或全球加速域名也要求有效备案，参见[阿里云说明](https://www.alibabacloud.com/help/en/cdn/user-guide/change-the-accelerated-region)与[腾讯云说明](https://intl.cloud.tencent.com/document/product/228/36178?lang=en)。这些是接入依赖，不能用调整当前 Cloudflare 缓存参数代替。

后续镜像必须复制同一批受签对象，保留完整 size/SHA、Range 和 identity 语义。所有镜像先完成不可变对象闭包校验，再提升同一发布序号；清单别名保持 no-store，对象使用内容寻址和长期不可变缓存。镜像不能成为新的代码签名权威，测速结果也不能放宽签名或内容验证。

运行时选择应按真实传输成绩排序，并在持续低吞吐时尝试另一条已准入线路，保留严格的续传校验。**本轮 engine2 仍只有两个编译固定 HTTPS 来源及不可用时回退，没有实现上述按吞吐测速选择，也没有国内镜像可供启用。**该分发改造和两地区的五分钟验收保持待完成。

本轮还准备了独立目录中的本地资源包重建试验：已证明 31 版全部 33 个包的头和索引可由受签目录确定性还原，小型 fixture 测试通过，未运行真实全量重建，也未写入正式更新器。即便全部资源可从旧文件重建，当前新 EXE 仍约 116 MB，慢链路下依然不能保证五分钟；不能把该试验当成已上线的离线迁移功能。

因此旧客户端桥 29/30 暂不激活，保持原根频道 23 和五职业频道 24。资源包目标可以独立验证和测试；只有地区分发与端到端性能证据满足门禁后，才让旧客户端自动迁移。
