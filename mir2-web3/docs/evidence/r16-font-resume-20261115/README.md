## 已实现

SC 原字库保留完整 16,437,364 字节与 SHA256 `2c76254f6fc379fddfce0a7e84fb5385bb135d3e399294f6eeb6680d0365b74b`，按原字节生成 **63 段，每段最多 256KiB**，没有更换字体、删除字形或降低 Native 六字体要求。生成器固定校验原文件，并把每段摘要嵌入 Worker，不依赖额外清单下载。

每段校验 206、精确 Content-Range、长度、无压缩编码及摘要，验证后写入独立的部分缓存。重启后重新校验缓存，只取缺段；63 段到齐后再次校验整份摘要，才发布完整 200 并写入正常字体缓存。旧的坏全体缓存也不能绕过校验。读者继续共享两条网络通道，排队时间不消耗请求期限；每段响应头 8 秒、正文 15 秒，存储拒绝不影响已验证的内存结果。来源和缓存身份在排队前固定，配置换代不能把旧请求改向新来源。

部分缓存最多另占一份约 16MB 的 SC 原字节，本轮在完整体落盘后仍保留，供完整缓存损坏时恢复；沿用版本清理与主动重置。它改善失败恢复，不减少字体总字节，也不保证首轮冷读已达标。

服务器忽略 Range 或没有取得任何有效段时，允许既有完整来源回退，仍须完整摘要。普通调用者自己的 Range 不进入此合并流程。缺少 Web Crypto 的旧环境保留既有整文件读取。本轮没有修改地图、战斗、授权、交易或服务器存档规则。

实际游戏首场另发现：登录框刚出现时输入账号被清空。`screenRef` 原在可见之后的被动 effect 同步，输入守卫可能读到上一屏；现在移到绘制前的 layout effect，同一提交的输入仍受原 epoch、可见性和登录忙碌守卫约束。实际 Page 提取回归在旧代码 4 过／1 失败，修复后首次输入和四种拒绝条件均通过。后续四次实际登录均绑定正确，原失败保留。
