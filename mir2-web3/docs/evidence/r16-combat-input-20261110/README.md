# R16 Web 桌面战斗输入验收

2026-11-10 基于共用分支 `7ceeef84e7` 对照 Windows R16。Web 使用固定素材和运行包，两个渲染模式均运行本机生产 Next 与普通 File Gateway。Windows 侧运行了 34 项定向测试，覆盖数字键、鼠标归属、前景重叠、权威物品编号和 300 毫秒边界。候选代码通过 203 项 Web 定向测试及 Stage5 的 520 组测试。 [构建来源和回执](receipt.json)

## 腰带与背包用药

真实浏览器登录同一份 30 级战士毕业档的隔离副本，只将初始生命改成 70。第一格是原有的五瓶中量药。WebGPU 和 WebGL2 各做两组物理输入，先连续两次按 `1`，再在下一可用时段按 `1` 后立刻点击腰带。两组均短于 300 毫秒。旧版每组发两条请求，四次成功回包后剩一瓶。修复版每组发一条并成功一次，正常注销后保留同一实例和三瓶药。聊天框里的 `1` 只进入文本。

普通背包的物品使用也进入同一个发送门。定向测试经过实际背包意图和 Page 发送边界，验证 299 毫秒拒绝，300 毫秒可以用。可以确认未发出的请求不会占用间隔。

## 普通 NPC 对话

用实际鼠标打开比奇的 Mir Guide Peter，对照普通对话的服务器回包和浏览器显示。旧版在对话内按 `1` 扣一瓶，修复版保持五瓶。鼠标关窗后约 50 毫秒发出一次合法用药，关闭快照约 449 毫秒后到，成功回包和正常注销均保存四瓶。再次打开同一 NPC 时，点未被遮挡的腰带也得到一次成功回包。较早候选在界面已关时仍用服务端旧对话拦截按键，失败回执保留。 [对话和腰带画面](npc-dialog.png)

## 普通背包与实战

使用未更改的毕业档，正常走到比奇的 `(298, 273)`。真实 `F9` 打开共享背包，实点窗内的空格发出 0 条世界指令。随后在窗外点击同一只天然刷新、相邻的鸡。旧版需先关背包才能打出有效攻击。修复版保持背包打开，服务端返回角色攻击与同一目标受击。最终生产构建从原始毕业档重复完整路线，两条渲染路径均保存角色位置并正常退出。已绘制前景和坐标失效时的点击归属由定向测试覆盖。 [打开背包的画面](bag-open-webgpu.png)

原始步行复测中出现过场景区域未覆盖当前坐标的提示，后续战斗回包仍正常。旧候选用战斗点的正常注销档直接重登，两条路径收到进场成功和世界状态，场景在 60 秒内未就绪。

## 战斗点冷重登

实际浏览器收到比奇地图 HTTP 200，返回的两层边界都覆盖 `(298, 273)`，缺失资源为 0。该地格没有独立素材、光照或碰撞记录，导出器会省略这一行。旧候选在渲染器启动前显示「重试」。修复按同地图及两层边界接纳非空地图，错图、空图、范围外位置和注销后迟到数据仍由定向测试验证。 [请求、边界和结果](sparse-scene-resume.json)

最终生产构建以两份此前正常退出的原样隔离档重登。WebGPU 在进场回执后约 1.76 秒场景就绪，WebGL2 约 1.70 秒。两条路径首个世界点击都命中天然鸡，之后正常注销并读回同一坐标和 30 级。32 项场景和资源测试、203 项战斗输入测试及 Stage5 的 520 组测试通过。持续追击、其他窗口组合、英雄和主角间的用药节流、长路线与其他地图、Windows 实际窗口和正式服均单列继续验证。 [重登画面](sparse-scene-resume.png)
