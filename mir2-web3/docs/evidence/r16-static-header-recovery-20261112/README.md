## 修复与证据

此前公网4张图片均在页面响应头阶段超时，不能仅凭旧记录认定唯一根因。代码和新增失败回归确认一个确定缺口：共享图片读取已与首个消费者的取消信号分离，但没有自己的响应头期限；同URL重试可以持续加入同一个不返回的请求。

每个来源现在最多等待7秒响应头，逾期撤销该次连接并沿原备用来源顺序继续。收到响应头后清理计时器，保留正在传输的正文；单个消费者取消仍不会中断其它消费者。不放宽页面原10秒响应头、15秒正文空闲、三次尝试和Native原120秒门槛；没有更改模型、Gateway、存档或素材。每个来源有独立期限，不承诺所有备用来源合计在7秒内完成。

- 55项定向及相邻检查通过，4项新增覆盖共享超时、逐来源期限、暂时失败后新读取及长正文；旧实现的共享超时测试明确失败。
- 实际Chrome加载原Worker和相同页面预热函数，故意让隔离源站4张图片不发响应头：旧版约30.5秒后全部失败且共享表仍有4项；新版约7.0秒从备用来源读到4份完整原PNG，逐一校验并写入缓存，共享表清空。持续8秒的原PNG正文也完整完成。
- 使用正式清单的浏览器安全R2备用地址复验，4份原PNG约7.5–7.7秒内完整返回、匹配摘要并缓存。此处只读真实公网素材，隔离源站仍为故障注入，不是公网游戏验收。
- 小型WASM未变，48个应用覆盖文件和固定素材逐项核验，生产构建通过。新的Worker会使缓存身份正常变化一次；没有实现跨版本迁移。
