# R16 本地联机拾取和阿洛行动顺序

## 普通拾取的编号冲突

无界面浏览器对照中，阿洛在 v1 收到玩家命中和可拾取蜡烛后，实际选择拾取。随后收到了地面对象移除，但没有蜡烛入包回执，记忆把领取记为未确认。 [浏览器原结果](baseline-browser-pickup-rejected.json)

用隔离 File Gateway 的两个普通新角色单独复现。双方初始蜡烛的编号均为 3。甲丢出自有蜡烛后，乙站在同格按普通方式拾取，编号冲突时乙仍只有 1 支。权威快照里地面蜡烛仍在。同类型的反向交接由没有该编号的角色接收，服务器正常发出入包回执。 [旧版实测](legacy-pickup-before.json)

本地共享 Zone 在领取票据已匹配、旧式库存编号冲突时，为进入接收方的物品副本分配空闲编号。原有物品和非冲突编号保留，正式的持久化资产领取仍验证原始资产身份。修复版乙保留编号 3，收到编号 4 的蜡烛，入包回执先于对象移除。反向交接后两人各 1 支，普通注销和重登一致。 [修复版实测](legacy-pickup-after.json) · [候选网关和源码指纹](candidate-build.json)

Gateway 新增编号冲突回归、原共享拾取及两个相邻领取用例通过。Simulation 两项编号冲突与堆叠测试及独立十一项精确资产测试通过。Node 的 101 项伙伴与 Web 回归通过。另一个原有测试在创建无回包用例的角色时失败，已用原 Gateway 测试二进制复现相同失败。

## Web 实战的已证范围

修复版用普通 Web 登录、邀请、走位和鼠标攻击。合成第三角色通过普通协议，在玩家命中天然鹿后丢下自己的蜡烛。无模型的 v1 阿洛观察到玩家命中、地面生成、蜡烛入包和鹿死亡，顺序为 93、94、99、113。阿洛背包从 1 支变为 2 支，随后有 7 次真实命中。

在同一浏览器用固定教学保存 v2。停止旧进程并用同一 SQLite 启动新进程，Web 读回同一角色和原教学。重新组队后的下一次探针未取得目标的玩家命中，v2 战后拾取顺序仍待验证。此前普通入队、安全区边界、放置距离和鼠标命中的探针停点均保留在隔离运行目录。 [浏览器 v1、教学和重启收据](candidate-browser-v1-and-restart.json)
