# R16 字库共享下载与公网时序

基于已提交 ab9947fcc0 的本地生产候选 ab9947fcc0eb-r16-fontshare-ea90557a。下列两个修复前公网观察使用 603e68a352；字库修复现已发布为 da134332ed，最新分项、失败与慢加载见[生产发布](production.md)。整体 1:1 Goal 继续。

公网复现首步 23.111 秒，而同段主线程没有超过 50 毫秒的长任务；全程最长 210 毫秒。独立 Node 健康请求同期约 62–157 毫秒，发送后约 1.47 秒观察到唯一移动准入计数增加，区间准入累计仅增加一次、763 微秒。该指标为聚合相关证据，尚非每个请求的服务器输出时间，不能据此断定网络或网关输出队列中的具体一层。后续仍查输出/传输链路。

原探针将 30 秒观察窗内收到回包记作功能通过，同时给出 ackWithinEightSeconds=false。本轮按后者保留性能失败，未把 23 秒视作首步通过。另一次为 3.404 秒。两轮 PerformanceObserver/定时器数据有效；高频 Chrome trace 超过采集上限且有数据丢失，只保留哈希和部分状态，未将其作为完整 CPU trace。

共用 HUD 的独立瓶颈是字库：繁中字库 11,941,968 字节，CSS 下载未结束时运行时又请求同一路径。第二次公网观察中首份约 153 秒，其他字体等待响应也超过 100 秒。WASM 约 60.7 秒下载完成后实例已运行，但字库未齐、HUD 仍未 ready；记录包含 Worker 原始 ResourceTiming 和状态变化。

浏览器 Worker 现将完整字库固定放入关键资源缓存，在首次正文下载和缓存写入期间共享同一个响应；CSS 与运行时各自取得完整克隆，不再只合并响应头。跨版本隔离、单个消费者离开、180 秒 lookup 退役不截断正文、16 项保留上限及 Range 请求分离均有定向检查。图片与其他资源策略保持，未删字、缩减语言或更换字体。

真实 Chrome 对照使用同一份原版繁中字库，逐块慢传输、CSS FontFace 解析和第二个普通 fetch 消费。旧版两次网络传输 23,883,936 字节；最终候选一次 11,941,968 字节，第二个消费者约 21.209→15.189 秒，少约 6.02 秒。两份内容 SHA256 均为 864727d210d54f2537bbe23b3a839436c3992af72de9322af5270897246bd44f，FontFace loaded，浏览器及服务关闭。此为受控本机传输，不写成公网提速比例。
