## 字体来源失败后保持同一读取名额

旧 Worker 在每次来源尝试结束时释放并发名额。SC 大字体的首个来源失败后，后备来源重新排在四套后续字体之后；上一场公网记录曾出现约 28 秒额外等待。现在同一个完整字体连续尝试既有后备来源，完成或全部失败才交还名额。

- 并发仍为两个；每个来源的原响应头等待、正文空闲、32 MiB 上限与重试规则保持。
- 原字体、来源顺序、缓存格式 sw8 和 Range／图片路径保持；未裁字体、合并来源正文或把响应头当作完整体。
- 同一字体仍由 CSS、Native 和预热共享；一个消费者离开不会取消另一个消费者。取消的排队读取、缺失负缓存、缓存隔离和 Worker 恢复继续回归。

实际 Chrome 的本机 HTTP 对照让 SC 首段断开，同时 TC 正在传输，四套字体排队。旧 Worker 在四套字体先行后约 1627 ms 才开始 SC 后备来源；新 Worker 约 2 ms、零后续字体先行。两场峰值均为两个完整字体，六套字体均完整解码且 SHA／缓存正确，图片可同时读取。[旧 Worker 的失败判定](browser-chain-before.json) · [新 Worker](browser-chain-after.json) · [六字体并发](browser-admission.json) · [混合来源失败重试](browser-retry.json)。这是有固定故障和延迟的本机夹具，不是公网速度估计。

完整来源链占用名额也可能让其他排队字体等待更久。这里只证明已进入读取的字体不会因换来源被新请求挤到队尾；整体公网收益仍由原完整冷启动门槛决定。

## 旧缓存清理不能丢掉登录或游戏

存在旧缓存、命名空间记录不存在或变化时，原 `maybeReloadAfterCacheNamespaceChange` 在清理确认后无条件等待 250 ms 刷新，并在排队时就标记“已刷新”。这轮旧档回放在刚填写并提交登录后被重载，表单清空；只有能力声明，没有走到完整认证。旧冻结构建的对照可正常认证。

新增 `lib/asset-namespace-reload.ts`，只允许可见、连接着的普通空登录页自动刷新。输入有内容、表单锁定、可见对话框、其他认证面板、选角或游戏中都不会刷新。250 ms 到期时再次核对当前界面和最新命名空间；仅在实际执行刷新前写入一次标记。资源配置和旧缓存清理继续完成，正在进行的操作保持。跳过的刷新不在当前会话里反复尝试；正常下次打开页面会使用已更新的 Worker。

15 项实际 Registrar 函数／DOM 状态回归中，原函数有 13 项失败；现在均通过，包括排队之后才输入、开始认证、进入游戏、隐藏页面、出现对话框及后来的配置取代旧配置。原空闲登录页仍按 250 ms 刷新一次。普通 WebSocket、认证载荷、服务器权限、存档与游戏规则没有改动。

## 输入、回归与失败记录

[146 项最终原始输出](regressions.txt)，7 个文件，零失败、跳过或取消。新增字体链 5 项、缓存刷新 15 项；相邻 Page 预热夹具漏接了后来新增的 `getRuntimeHeaderPriority`，这轮接入真实实现并增加两项 Page 回调／取消检查，原 12 项缺依赖失败也保留。[原失败与修正依据](retained-failures.json)。

独立镜像由此前冻结且通过资格的 f310 镜像复制，叠加本次七个源码／测试文件。第一版逐一检查了 2176 个前端输入，新旧镜像仅 Worker 不同；旧镜像与 Git 的唯一差别是既有发行用 Bevy 元数据，逐字节匹配此前冻结的生成输入，未当作新变更。第二版另加 Registrar 刷新保护。原始输入和两次构建均保留，29 份无关内容 WIP 的 SHA 与上一提交时相同，未打包进独立镜像。[构建与输入](source-inputs.json) · [最终八份夹具 SHA](fixture-source-pins.json)。私人认证材料、账号库、浏览器档案和原始认证流量不入仓库。

早期夹具失败没有改判成功：

- R1–R4／R6 的登录被自动刷新打断；可见性对照未解释问题。R5 的旧构建可认证，但并非整个基线流程通过。
- R7 修复后认证通过，随后“六套旧缓存必须存在”的准备断言失败；真实命名空间清理会让这些缓存失效。最终保留实际缺失，游戏正常加载，仍要求完整六字体、113/113 和原 120 秒。
- R8／R9 的“至少一次补读”断言与本来允许“已有完整状态就不重复读”的设计不符。最终仍限制最多三次，并额外要求实际较晚的权威快照匹配地图、玩家、任务，以及同连接／会话的新场景控件。缺状态时的读分支仍由实际 Page 单元回归强制覆盖。
- 新加的只读认证观察器曾把 `undefined` 当成字符串结果，随后访问不存在的 payload，遮住五条发送观察，造成 R9 虽实际保存仍整体失败。旧记录中的零观察数不能当成真实零请求。修正后用实际提取函数验证空 payload，最终两场均观察到一次换图补读和零协议错误。
