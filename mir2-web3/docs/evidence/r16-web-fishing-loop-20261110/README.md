# R16 比奇钓鱼窗口和权威回执

基线为 `codex/windows-player-journey` 的 `7dd452d45a`。使用隔离的 R16 `platinum_fiveclass` Gateway、同一 30 级道士 File 副本和普通 Chrome 键鼠输入。鱼竿、鱼钩、鱼饵和绕线轮先用完整内容档的普通商店和装备协议取得。试玩服、原始档案和正式用户数据分开。

## 冷登录和收竿

实拍旧路径先有朝向左上的已知站姿。点击岸边后，画面先转向左下、服务器还记录左上，姿势查询变为未知。收到同位置左下的真实 `UserLocation` 后，旧路径一直无法恢复。修复只保留同一已确认角色的初始站姿依据，方向不一致时继续返回未知。对齐后恢复读取。视图早于首次完整快照时也可接纳一次站姿依据。身份退休、重复角色、已出现其他动作及陈旧标识仍不能靠默认站姿恢复。 [真实转向前后](browser-turn-and-tackle.json) · [两版实际 WASM 对照](cold-wasm-comparison.json)

WebGPU 与 WebGL2 共享画布的本机生产页面用实际左键转向、再点击水面。真实进度及咬钩打开 Windows R16 样式的状态窗。右上角发送 `FishingCast(false)`，启用后的 Esc 也能收竿，关闭该开关时 Esc 不发送钓鱼包。无咬钩的提前收竿和正常注销都有回执。两场各消耗 3 个鱼饵，File 读回剩余 12 个。 [两条浏览器路径](browser-turn-and-tackle.json)

## 装配、自动钓鱼和渔获

普通菜单或 N 打开鱼具窗。用左键选鱼钩或鱼饵，点实际空背包格卸下，再从背包选回并点对应鱼竿槽。原鱼钩和 15 个鱼饵各两次匹配回包，经后续完整快照、正常退出和同角色再进城确认编号、数量及原绕线轮保留。这些交互复用现有 Web 背包兼容窗和普通 `EquipSlotItem`／`RemoveSlotItem`，成功回包及后续权威布局一起确认，等待期间保护物品操作。鱼具中的实物标识在缺少图标资料时仍可读。 [装卸及重登](browser-autocast-and-relog.json) · [鱼具窗](tackle.png)

旧候选扣饵和耐久期间会短暂失去可读鱼竿，自动钓鱼按钮随之消失。修复后的关闭依赖当前角色的有效钓鱼状态，开启仍需验证绕线轮。WebGPU 实测开启、一次服务器自动重抛、关闭、等待 950 毫秒无额外扣饵、咬钩时手动收竿并退出，落盘剩余 11 个鱼饵。较早候选的独立普通自动钓鱼得到两件奖励，隔离档确认物品，第二件匹配实际 `GainedItem`。当时自动关闭与正常注销探针失败，奖励结果单独记录。 [开关与奖励](browser-autocast-and-relog.json) · [关闭后仍可手动收竿](autocast-off.png)

窗口采用已提交的 Windows R16 图集、槽位和操作。该版本状态窗的 `Fishing` 字样为静态素材，实际收竿用右上角或启用后的 Esc。Crystal 源码中的独立咬钩按钮、角色抛竿和收线身体帧、鱼线表现、鱼具拖拽、Windows 实机和最终真人验收继续单列。

## 最终本机候选

## 冷登录首竿时序

WebSocket 的快速转向跳过个人运行时调度，旧路径在成功抛竿后继续等待 15 秒登录缓冲。两端共用的 Gateway 现在只在有效抛竿返回本人 0% 确认后，用现有 75 毫秒输入唤醒调度。失败、收竿和自动钓鱼开关无此唤醒。编译及 4 项定向 Gateway 回归通过。

同一比奇 File 基础档、同一水格和相近输入时点分别复跑已知旧版与新 Gateway。实际 WebGPU 首个 25% 包从 9.662 秒降到 0.698 秒。Windows R16 Rust 正式传输从 9.254 秒降到 0.684 秒。时间起点均为实际 0% 抛竿确认。两条路径各一竿、正常收竿和注销，四份副本均剩鱼饵 14、鱼竿耐久 9999、鱼钩耐久 7999。绕线轮按实际渔获结算，在各自修复前后结果一致。Windows 首轮探针因把数字角色 ID 当字符串等待超时，修正探针后双轮通过。四轮服务关闭，源档哈希一致。 [时序、存档和原始回执散列](cold-first-cast-timing.json)

Windows 路径使用无界面正式传输构建。钓鱼仍沿用 R16 每次个人维护推进 25% 的规则，原版 Crystal 的首轮定时与后续步进、原始 TCP 路径、Windows 窗口和公开发布分开验收。

## 鱼具和背包之间拖放

Windows R16 在按下时选择物品，松手时命中当前格。Web 在同一前景界面捕获这次输入，松手按实际可见格和物品来源确认，再交给原装卸、成功回包和权威快照。关闭、切页、角色变化或焦点丢失会结束拖放。原两次点击与键盘操作继续通过。

旧生产构建的双向真实拖放均发出零条装卸指令，同样物品的两次点击通过。新生产 WebGPU 候选把原 15 个鱼饵一次拖入背包，正常注销和全新会话读回，再一次拖回鱼竿并复验重登。每次各一条请求和成功回包，原物品编号与数量一致。占用格、错误类型、原格和落到世界区域的七次试验均无误发。另有鱼钩双向点击、三次正常注销、517 组回归和 TypeScript 检查。首轮浏览器探针把共享画布误判为无效地图位置，改用已验收的同一岸边实点后完成复测。 [精简回执](tackle-drag.json)
