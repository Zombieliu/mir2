# R16 字库与运行包并行、同版镜像恢复候选

本轮基于已提交 R16 `32259b1435b091d69c2b6c5c5dc62dccebf5625b`。最终本地候选 `32259b1435b0-font-overlap-2dbaf38a`，构建 `AZmSgd2NkoFseK3664CjI`。**尚未发布，正式站仍为 72c00d20ae；整体 100% 1:1 Candidate 未完成。**

## 改动与检查

- 首个可玩画面、运行策略和 GPU 支持检查通过后，以两个后台任务提前读取 Native 原有六份字库，与运行包下载重叠。离开游戏或运行包失败时取消本次预取；未启用运行包、触屏兼容路径及首帧之前不触发。
- 字库预取沿用完整正文、停传、取消与体积检查。字体、字形、语言、运行包、世界规则及 Native 渲染器均未替换；运行包与三份小型 WASM 的字节保持原样。
- Worker 原先只尝试首个当前版本镜像，失败就返回应用源。现在先尝试其余已配置的同版镜像，再返回应用源；旧发行版本仍在后面。每来源 8 秒响应头、15 秒正文停传和 32 MiB 正文上限保持不变，不拼接失败来源的字节。
- 干净候选通过 **132 项**定向及相邻检查、生产构建与 TypeScript。保留 Page 未提前读取的 1 项红灯和旧 Worker 跳过同版备用镜像的 3 项红灯。

## 真实 Chrome 的同条件对照

使用固定发行版本的真实字节，运行包首轮响应延迟 25 秒，简中字库正文延迟 12 秒；六份字库逐文件验证摘要。它们通过真实 Worker/HTTP 读取，不预填缓存、不伪造世界或移动回包。基线与候选使用独立构建、全新 Chrome 存储、同一普通协议及隔离 File 夹具。

| 情形 | 首轮 Native HUD 就绪 | 彻底重开后 | 结果 |
| --- | --- | --- | --- |
| 已提交基线，六份字库均受控 | 38.1 秒 | 1.2 秒 | 字库在运行包完成后才请求 |
| 最终候选，默认 WebGPU | 26.3 秒 | 1.3 秒 | 简中字库在运行包完成前完整读完 |
| 最终候选，共享 WebGL2，六个首入口均不返回响应头 | 36.5 秒 | 1.2 秒 | 六次到达原响应头期限，随后从同版备用入口完整读取六份字体，未请求故意停传的应用字体源 |

默认路径在此受控条件下减少约 **11.8 秒**。这是移除串行等待的机制对照，不是公网速度保证。三行均完成两轮 113/113 预取、原字体任务窗/Q、8 次关窗立即物理移动、浏览器完全关闭后同角色重进、反向一步和两次正常注销保存。包标识分别核对为 `webgpu` / `webgl2-shared`。

最终候选真实 CDN 复测的原 **120 秒冷启动门槛仍失败**。相对运行包请求起点，完整 WASM 约 108.8 秒读回；简中字库先在两个同版入口各等待原 8 秒响应头期限，再进入测试中故意停传 160 秒的应用源。预取三次各收到 1 KiB 后按原停传规则取消，Native 后续收到完整字体约在 208.2 秒。额外恢复观察后任务窗、8 次关窗立即移动、113/113、正常保存通过，完全重开约 0.8 秒就绪并反向移动、再次保存；**整轮仍为 false**，未放宽原门槛。

这个用例让运行包和镜像走真实 CDN，同时故意延迟应用字体回退；它不等同于普通公网访问的无故障耗时。本轮不宣称公网冷启动已解决。全部自建进程关闭，原档摘要不变。

另外用普通网络的独立 Chrome context 读取前 64 KiB：首入口 `reload` 约 815 ms、第二入口约 483 ms、首入口默认缓存约 504 ms、首入口 `Range` 约 772 ms 返回响应头；状态分别为 200/200/200/206，四份前缀均匹配原字体。这里只消费前缀，不证明整文件速度或分段读取更快。空闲条件没有复现启动中的头部超时，下一步要记录启动并发时的排队、发出请求及收头时间，不能直接把问题归为源文件不可用。

## 保留的失败和方法修正

- 最初镜像设置在选角后，完整繁中字库已在登录回包时开始请求。两次中只有五份字体受控，不能拿来作同条件速度比较。中间候选那次繁中字库约 177 秒才完成，冷启动超过 120 秒，整体为 false；后续恢复、重开和保存通过并不覆盖失败。
- 修正对照夹具后，在点击登录前配置字体镜像，并在普通 manifest 重配后保留该测试配置。其后基线与候选都实际从受控 HTTP 来源读取六份完整字库，才进行上述比较。
- 仅提前读取的旧 Worker 候选在真实 CDN 的首入口响应头超时后返回了故意停传的应用源；首三次预取只收到 1 KiB，按原正文停传规则取消。运行包约 118.6 秒完成，简中字库约 205 秒才完整到达。原 120 秒冷启动失败保留；后续恢复/正常保存及缓存重开约 0.8 秒分别记录。这次证据促成本轮同版备用入口修复。
- 早期测试夹具的相对路径、缺少既有上下文、模拟计时器未推进导致的失败/取消输出保存在本机；不把夹具修正记作产品能力。
