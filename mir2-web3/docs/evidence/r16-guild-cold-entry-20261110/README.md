# R16 公会双开冷进入对照

在旧归档和当前源的 Next 开发模式分别复现会长页面回到登录。Chromium 记录了第二次文档请求，导航类型为 `reload`，调用栈位于 Next `client/dev/hot-reloader/app/web-socket.js` 的 `handleMessage`。刷新同一时刻，HMR `sync` 的编译哈希发生变化。两次刷新分别早于对端首条游戏 WebSocket 1119 ms 和 1575 ms，观察中没有会长的服务端 `Disconnect`、`ReturnToLogin` 或应用主动关闭。首次历史失败缺少调用栈，独立保留。

当前本机生产构建使用 `/game`。强制 WebGL2 与默认渲染路径各通过 12 项普通界面断言。两人分别冷加载，每人一次文档请求。会长保持在线，实际看到另一端的职级更新，再正常注销并重进读回结果。每轮会长三次 `StartGame(4)` 和三次注销，对端各一次。无 HMR、页面、控制台和网络错误。隔离服务已退出，原始档案哈希一致。 [调用栈、生产回合及保全](comparison.json)
