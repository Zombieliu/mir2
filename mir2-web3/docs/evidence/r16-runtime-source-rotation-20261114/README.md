## 原问题与改动

上一轮公网读回同一 `pkg-webgpu` 包时，本站先无头超时，CDN 两次在接近完整时断流，之后本站完整恢复。失败的两次 CDN 正文合计约 62.47 MB 解码字节；Native 就绪观测为首帧后 239.322 秒，原 120 秒资格 false。不是三个后端同时下载；传输已使用压缩。原失败及实际记录仍见[上一轮正式回执](../r16-route-direction-20261113/production/README.md)。

现在只有最后一个来源发生“收到正数字节后的可恢复正文失败”时，原本已有的一次额外重试优先轮换到较早的临时失败来源。若还需原有的单次 owner 授权恢复组，避免紧接着重复刚失败的来源。零字节和 HTTP 状态失败的原顺序保留，403/404 不获得额外重试资格。

每组来源数加最多一次额外重试、最多两组、原 1 秒恢复冷却、8 秒非末来源响应头、15 秒正文 idle、原初始化／总量／取消／owner 边界均保留。没有增加模型调用、Gateway 权限、存档变更或运行包版本。
