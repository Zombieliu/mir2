# R16 换图后的任务导航与个人状态补读

2026-11-15：修复普通入口换图后，Web 任务导航消失、攻击模式停在同步中的问题。两种渲染路径完成实际跨图、注销、重登、新目标及正常存档；110 项回归和独立生产构建通过。当前记录为本地候选 `b9-map-world-refresh-f9d91453`，基于已发布的 `b9acf175fa`。正式发布另记，不能将本地通过写成公网完成。

## 问题与改动

原版普通入口发送 `MapInformation`，随后给出新地图的权威落点。Web 会撤销旧场景的完整个人状态和旧导航，但此路径没有主动取得新的完整状态。角色和场景可以出现，任务导航与攻击模式的完整上下文却一直缺失。[修前实际画面](before-missing-guidance.png)。

新增 `apps/web/lib/map-world-baseline-refresh.ts`，由 `app/page.tsx` 的实际地图入口接入：

- 已有完整状态的角色换图后，延后补读普通 `clientVersion` 全量状态，最多三次；普通初次 `StartGame` 不重复请求启动数据。
- 每次发送前核对实际 socket、连接、角色会话、场景、玩家编号和地图。已收到合格的新地图状态就停止补读。
- `StartGame`、正常注销、返回登录和组件销毁会取消待处理补读；旧连接、旧角色或旧场景不能继续发送。
- 原导航仍立即撤销。补读不恢复旧目标，不发送移动、购买、任务完成或奖励指令，接收结果继续经过原有完整状态校验。

未改 Gateway、存档结构、战斗规则、素材或共用 Rust 运行包。独立候选使用冻结的 b9 前端，叠加本次三个源码／测试文件；没有把共享工作区的其他未提交内容打包进去。

## 实际流程

每场从此前正常游玩保存的 `SpawnSmoke` 开始。先用普通认证和七次正常走路，从比奇 `(322,293)` 走入原数据中的试剂店入口 `(326,288)`，正常注销保存，再在浏览器登录同一角色。准备阶段使用现有普通 `clientVersion` 读取换图后的完整观察；没有改坐标、给物品或注入传送。

浏览器内实际操作如下：

1. 在试剂店 `0108`、地图编号 4 的 `(8,12)`，点击共用 Native 任务导航。实际 Rust 规划器选择本图出口 `(10,13)`，半径 0；两次正常走路触发真实 `MapInformation`，回到地图 `0`、编号 1。
2. 配置中的落点为 `(326,289)`，共享 Zone 因关闭的门格选择可站立邻格 `(325,290)`。以实际 `UserLocation` 为准，浏览器落点与其一致；两次旧图移动均发生在换图回包之前，回包后没有旧路线移动，连最初 100 ms 也没有。
3. Web 自动补读一次完整状态，实际任务导航重新出现，任务 `2110003` 仍在进行中。画面中的攻击模式恢复为和平。
4. 再点任务导航，扣住新地图第一块真实碰撞响应。未发出移动时正常注销；收到注销确认后，原样释放响应。旧会话没有调用地图 0 的规划器，也没有因晚到数据而起步。
5. 刷新页面，建立第二条浏览器 socket，普通密码登录同一角色。落点保持 `(325,290)`，没有继承旧目标。通过游戏补给入口选择药品商人 `(324,291)`，实际新规划从当前落点出发，确认已在合法两格范围内，不进入 NPC 所在格。
6. 玩家再正常向下走一步，到 `(325,291)`，正常注销。角色元数据及金币、背包、装备、任务、技能等 12 个列明字段逐项保持，最终权威位置正确保存。
