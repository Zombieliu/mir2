## 加载长尾的下一步

[同场静态与 Worker 字体观察](static-transport-comparison.json)保留两场独立时钟、完整静态请求计数、响应头、完整体和失败记录。R2 页面静态观察为 626 条，零丢弃、零截断且探针已关闭。页面与 Worker 行有重叠，不能相加字节数。Header 优先级里浏览器的 `atMs` 与场次时钟不同，比较时使用 `epochMs - clockEpochMs`。

R2 可直接观察到：

- Wasm 的前两个来源各等约 8 秒后取消；第三次请求才返回完整体。不能把首次响应头或部分字节算作运行包就绪。
- TC 的首次上游请求已收到 200 响应头和部分体，随后被取消；Worker 最终向页面返回 504。后一次 TC 完整体才成功，不应把第一次的部分体当成功缓存。
- SC 当前 CDN 候选在约 8 秒后取消；它的同版本 hotlink 候选到 28 秒后才开始。期间四个小字体的应用来源分别等待约 7 秒后取消。SC 后备候选最终用约 23.3 秒完成。
- 代码中的字体并发限制作用于每个来源尝试，回退会重新排队。下一项先验证它是否让同一完整字体的后备读取反复排在新请求之后，以及当前版本来源是否总在旧版本之前；再做最小修复和原门槛资格测试。

这些记录证明加载路径存在长尾，尚不证明 f310 的换图补读造成性能退化；两场不是配对网络实验。此处没有据此修改并发、放宽超时、少读字体或发布未经重新验收的候选。
