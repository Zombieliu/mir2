# 阿洛的 Web 体验与费用页

Windows R16 的培养页有体验自述，行动页可查看服务用量和费用。Web 补齐这两个入口及对应布局。回访来源、提醒次数、选择理由和教学反馈都使用当前角色的私有 `trialEvent` 接口。服务意向只在有当次体验和已配置报价时开放。费用从账本读取，缺少实计成本时显示未计量。

2026-11-09 在本机隔离 File 世界用无界面 Chrome 实测。通过正常建号、建角、登录和选角进入比奇。点击固定教学后，阿洛从 v1 升至 v2，三项组队习惯从否变为是。记录了一次收到提醒、因共同经历选择阿洛且理解教学的测试体验。费用页显示 0 次模型调用、0 CNY 模型金额、托管未计量，且未配置服务报价。 [体验页](experience-selection.png) · [费用页](usage-costs.png)

浏览器下载的 v2 档案与服务器 SHA-256 一致，并用受信任密钥通过 HMAC 验签。正常停止并启动新的规则运行器，沿用同一 SQLite，再打开伙伴页。角色身份、v2 习惯、原教学、体验及选择记录均保留。页面异常为 0，隔离进程均已退出。 [完整收据和源码指纹](receipt.json)

## 新实例导入与普通协作

复测时把刚下载的签名档案导入全新的 SQLite，完整成长逐项相等。新的运行器使用导入库，原体验账本作为独立数据继续使用。Web 读到同一身份、原教学与 v2 习惯。用伙伴按钮普通邀请后，服务器确认两人队伍。主人键盘走位时阿洛跟随移动 7 格，保持在主人 3 格内。普通点击天然鹿后，服务器分别记录玩家和阿洛各 6 次真实命中，随后确认鹿死亡。此轮未对照教学前后同一掉落的拾取顺序。 [导入后入队](imported-alo-party.png) · [组队、移动和战斗收据](portable-party-combat.json)

再次复测体验页，开始后从账本读回当前体验的来源和提醒次数。返回培养再重新打开，仍显示「收到提醒」和 1 次。原先按草稿渲染会在确认后显示默认值。 [进行中界面](active-visit.png) · [读回收据](active-visit.json)

最早的探针因仅浏览器 Origin 许可拒绝 Node 的普通连接而退出，随后改用现有回环测试配置。第二轮探针用十六进制文本校验 HMAC，换成与运行器一致的解码字节后通过。导入后的第一条野外路线在限定步数内未接近稻草人，换另一条普通路线实际遇到并击杀了鹿。最终 98 项回归及 TypeScript 通过。模型、跨端同档、战斗与掉落优先级对照及公开发行仍需独立验证。
