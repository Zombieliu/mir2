# R16 自动寻路：真实玩家动态占住第三条边

2026-11-15：默认英文、共享 WebGL2 繁体两场均通过。每场使用同一隔离 Shared Zone 中的两个真实客户端：主角色通过浏览器正常登录和操作，挡路角色通过普通协议正常登录、建角、进场和走路。挡路者不是个人 Session 中生成的假玩家。

本轮复用已发布的前端 `b9acf175fad0bb582f20fd76282580f179c4b0d2`，没有修改游戏逻辑或重新部署网站。正式入口仍为 <https://numeron.obelisk.build/game>；公网发布资格见[上一轮正式回放](../r16-runtime-header-priority-20261115/production/README.md)。本轮网关为本地 `9244ce3dd7cd2129a70e650be1430e971b6c96ab`，不能据此声称公网 `fd3` 的双钱包占位测试已通过。

## 实际经过

1. 读取角色原有的进行中任务，先验证当前狩猎区的零步到达，再从游戏入口选择药品补给商人。原始 NPC 数据中的地图文件为 `0`、地图编号为 `1`，目标为 `(324,291)`，允许到达半径为 2 格。
2. 浏览器角色位于 `(288,616)`。原版 Rust 规划器给出实际路线；此时 `(287,612)` 尚未被占用。
3. 用真实地面点击发出朝 `(289,615)` 的手动第一步。仅在本机 QA 中短暂扣住这条原样的出站消息；所有服务器入站消息保持正常。随后另一名在线玩家从 `(286,612)` 正常走入 `(287,612)`。
4. 主浏览器实际收到该玩家的位置，自己的权威位置仍是 `(288,616)`。释放原手动消息后，自动执行器从已确认的 `(289,615)` 重算；被占点恰好是剩余路线的第三条边，且原路线包含转弯。
5. 重算继续使用原补给目标、地图和半径。新路线先走 `(288,614) → (287,613) → (286,612) → (286,611)`，第一条自动指令为 `run UpLeft`。挡路者一直在线，主角色未进入被占格，最终到达合法邻格 `(322,293)`。
6. 两名角色均正常注销并保存。主角色保存于 `(322,293)`，挡路者保存于 `(287,612)`；主角色元数据与金币、物品、任务、技能等 12 个列明字段保持不变。

```text
node mir2-web3/apps/web/scripts/smoke-r16-route-intent-gate.mjs <输出JSON绝对路径> <Chrome或Edge绝对路径> <含Playwright的package.json绝对路径>
```
