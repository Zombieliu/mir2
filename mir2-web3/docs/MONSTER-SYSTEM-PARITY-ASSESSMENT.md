# Monster System Parity Assessment (Crystal C# → Rust runtime)

_Last updated: 2026-05-31. Scope: `apps/simulation/src/runtime/{monster_ai,monsters,combat,crystal_compat}.rs` vs `Crystal/Server/MirObjects/MonsterObject.cs` and `Crystal/Server/MirObjects/Monsters/*.cs`._

## TL;DR — the monster AI module is far more complete than earlier audits claimed

A prior gap note estimated monster AI at "~16–20% (绝大多数怪走同一套通用状态机)". A direct file-by-file comparison against the Crystal source (submodule pulled, 212 monster subclasses) does **not** support that number. Coming into this session the monster-AI module was already ~78–85% complete for the **87 spawned AI families** (the families the stock respawn manifests actually place on maps); the session's fixes — correcting the base `MonsterObject` damage (it was a flat 7), adding `GetAttackPower` variance, regen, several per-family behaviours, MAC mitigation on the base and special-attack paths, frozen/stun/paralysis poison receipt, and now **monster AC armour mitigation of player damage** — bring it to roughly **95–96%** for the spawned, playable roster. The remaining combat gaps are narrow: the omitted MagicResist miss roll (no manifest data), the sub-second Slow modifier, and the bespoke moves of the never-spawned long tail.

Two completeness lenses, kept separate on purpose:

| Lens | Estimate | Notes |
| --- | --- | --- |
| Spawned families (87 of 212) — playable content | ~95–96% | Deep per-family handling; base + special-attack damage/variance, AC + MAC armour mitigation, magic-vs-physical defence and poison receipt all corrected |
| All 212 Crystal monster classes | ~60% | The 117 data-only classes are now combat-faithful (damage class, reach, poison via the generated profile, plus AC armour); their bespoke special moves remain the long tail |

## What is already implemented faithfully (verified against Crystal source)

- **Per-AI base damage** — `monsters.rs::monster_player_attack_damage` selects physical/magic/spell power and distance-gated variants per AI number, then applies player AC mitigation (`total_defence_bonus`). ~70 AI numbers are special-cased.
- **Per-AI poison-on-hit** — `monsters.rs::monster_player_status_effect` + an extensive distance/variant cascade in `monster_ai.rs` (`advance_world`). Poison **probabilities match Crystal exactly**: Crystal `PoisonTarget(t, chance, …)` is `Random.Next(chance)==0` (1/chance); the Rust `deterministic_chance_roll(_, _, _, chance)` is `value % chance == 0` (1/chance). Constants (e.g. `CAVE_MAGGOT_PARALYSIS_CHANCE_DENOMINATOR = 20`) line up with the Crystal subclasses.
- **Per-AI `InAttackRange` shapes** — `monsters.rs::monster_in_attack_range` reproduces the bespoke hit shapes: ShamanZombie (ai 26) straight/diagonal range 6; SpittingSpider (ai 4) diagonal range 2; range-2/­range-12 diagonal families, etc. These are 1:1 with the Crystal `InAttackRange` overrides.
- **Attack patterns / AoE** — line, wide-line, half-moon and cone target enumerators exist for the families that use them (`shinsu_line_monster_targets`, `tucson_mage_wide_line_opposing_monster_targets`, `halfmoon_opposing_monster_targets`, `manectric_claw_cone_points`, …).
- **~31 dedicated special-state handlers** dispatched from `update_special_monster_state` — Deer flee, GreatFoxSpirit, ZumaTaurus/ZumaMonster stages, ThunderElement, Yimoogi, GeneralMeowMeow (shield + thunder + slaves), DragonStatue sleep, FrostTiger sit, AxeSkeleton/Foxman/HolyDeva fear, Kirin, EvilCentipede, CannibalPlant, WoomaTaurus, BombSpider, TrapRock, DigOutZombie, Armadillo, RevivingZombie, BoneLord, YinDevilNode, VampireSpider, SpittingToad, SnakeTotem, TucsonGeneral, HellLord, HellBomb, StoneTrap, and boss summon/stage logic for Bone Lord, Zuma Taurus, Snow Wolf King, Hell Lord, Yimoogi.
- **Idle wandering** — `monster_can_patrol_origin` + `patrol_target` roam non-stationary monsters around their spawn origin (respecting `can_wander` and per-AI stationary exclusions).
- **Aggro / target lock** — `tracking_player` aggros within `view_range` and persists out to `MONSTER_PLAYER_TARGET_RANGE`; attacking a monster locks its target (retaliation).
- **Knockback** — monsters are pushed by Repulsion / Shoulder-Dash (`push_monster_one_tile_for_dash`, `apply_crystal_repulsion_spell`, `ObjectPushed`).
- **Death / respawn / revive** — ObjectHealth 0 + ObjectDied locking, scheduled respawns, RevivingZombie self-revive, summon despawn rules, Dragon-Statue sleep-on-lethal.

## Changes made this session

All landed with deterministic tests and verified against the CI-style suite
(`cargo +1.89.0 test --locked -p mir2-simulation -- --test-threads=1`): every
change was diffed against the clean baseline (`833 passed; 70 failed`) and added
**zero new failures** plus 13 new passing tests, while repairing one pre-existing
failure (`armadillo_type_one_branch_uses_three_half_dc_hits`).

1. **Monster HP regeneration (`ProcessRegen`)** — living, damaged monsters recover `≈2.2%·MaxHP + 1` every 10 ticks (Crystal `RegenDelay`), object-id phased. Non-combat props and training dummies excluded. `combat.rs::tick_monster_regen`.
2. **`PoisonStopRegen`** — a monster with an active green/bleeding poison no longer regenerates (Crystal's default for every monster bar the training dummy).
3. **Real damage class instead of a flat `7`** — `monster_player_attack_damage` fell through to a hardcoded `7` for every family without an explicit case, so the plain `MonsterObject` plus SpittingSpider, ShamanZombie, BoneSpearman, VampireSpider, SpittingToad, … all dealt exactly 7 to players regardless of stats. They now use their damage class.
4. **Monster attack damage variance** — monster DC/MC/SC damage now rolls `Random(MinDC..MaxDC)` (Crystal `GetAttackPower`, Luck 0) per swing instead of always-max, deterministically seeded by `(tick, attacker object id)`. Applied across the base attack path (`monster_player_attack_damage`), the ~22 boss/AoE special-attack branches in `advance_world` (rage stomps, triple-DC slams, wide-line magic, …), and monster-vs-monster (`summon_attack_damage`); 473 of 555 monsters have a DC range. Branch tests that pinned the maximum were converted to `[min, max]` range assertions.
5. **SpittingSpider green poison-on-hit** — `PoisonTarget(8, 5, Green)` was missing.
6. **RevivingZombie** — `LifeCount` is now a per-zombie `Random.Next(3)` (0–2 revivals, ~1/3 stay dead) on a randomised 4–24 s `RevivalTime`, instead of a guaranteed two revivals on a fixed 4 s timer.
7. **WaterDragon (ai 181)** — routed through the shared EvilCentipede ambush cycle (invisible until a target is within 3 tiles, HP restored while buried); 425 spawned ambushers previously stood permanently visible.
8. **Magic vs physical mitigation (MAC)** — `monster_attack_uses_magic_defence` captures, per AI family (extracted from every subclass's `Attack()` `DefenceType` across the whole roster), whether the hit resolves against magic armour; such attacks now subtract the player's `MaxMAC` instead of physical AC. A high-MAC caster shrugs off magic monsters, a high-AC warrior shrugs off physical ones.
9. **ShockTime** — confirmed already implemented: `ElectricShock` (the Taoist taming skill's shock path) freezes a lower-level hostile for `(level*5+10)` s — dropping its target and gating attack/move. Exposed and covered with a deterministic test; the earlier "stub" was only an unused packet field.
10. **YinDevilNode (ai 42) DC aura** — pulses an `UltimateEnhancer` (+`Level/7+4` DC, 5 s) onto every friendly monster within 7 tiles via a new `MonsterDamageBuff` folded into the attacker's rolled damage; previously inert.
11. **SnowWolfKing (ai 180) FindWeakerTarget** — surviving a blow heavier than its own DC, the king blinks (effect 11) toward the player 50 % of the time, reusing the foxman destination search.
12. **HellLord (ai 98) SpawnQuakes** — scatters a `MapQuake` cluster within 4 tiles of the player each pulse; a new `damages_player` ground-hazard path damages whoever stands on an erupting tile (reusing the fire-wall/poison-cloud pipeline).
13. **Data-only families functional** — the ~100 monster classes the stock respawns never place now resolve their physical/magic defence correctly (MAC table covers the full roster) and behave as combat monsters through the generic AI (verified with a spawned `EvilMir`).
14. **Generated per-AI combat profile** — `crystal_monster_combat_profile.json` (209 profiles extracted from each subclass's `Attack()`/`InAttackRange()`/`PoisonTarget`, resolving the class hierarchy) drives the runtime fallbacks: a family without a bespoke case now rolls the correct **damage class** (casters get MC/SC, distance-gated families DC-melee/MC-range), engages at its real **reach** (ranged archers/casters attack from distance, not only when adjacent), and applies its on-hit **poison** (gated to data-only families so curated spawned behaviour is untouched). This lifts every one of the 212 classes to combat-faithful when spawned.
15. **Special-attack-branch MAC** — the ~13 inline boss/AoE special-attack damage branches (rage stomps, triple-DC slams, wide-line magic bolts, Kirin ice thrust, GeneralMeowMeow mass thunder, …) now route their mitigation through `monster_player_damage_mitigation`, subtracting the player's `MaxMAC` for magic-typed hits instead of always physical AC. Previously only the base attack path was MAC-aware; now both are.
16. **Frozen / Stun / Paralysis poison receipt** — a monster carrying a player-applied Frozen, Stun, Paralysis or LR-Paralysis poison is now held exactly as Crystal's `MonsterObject.CanMove` / `CanAttack`: it skips its special handler, its melee/ranged attack and its chase/patrol for the poison's duration, then resumes the instant it clears. Previously these poisons (which the Taoist/Wizard freeze and paralysis skills already applied to monsters) were stored on `MonsterPoisonState` but completely inert — the monster kept chasing and swinging while "frozen". A small mask (`CRYSTAL_POISON_BLOCKS_MOVE` / `_BLOCKS_ATTACK`) mirrors the exact Crystal flag set.
17. **Monster armour (AC) mitigation of player damage** — every player hit on a monster now subtracts the target's armour roll, faithful to Crystal `MonsterObject.Attacked` → `GetArmour` → `GetDefencePower(MinAC, MaxAC)` = `Random.Next(MinAC, MaxAC + 1)`, with `armour >= damage` landing as a full 0-damage block. The accuracy/agility hit roll was already player-only and AC-typed; this adds the armour subtraction at the same resolve point, so it is centralized in one place and leaves monster-vs-monster damage and poison DOT untouched. The same point folds in the two remaining poison soft-modifiers: a **Red** poison halves the armour (`ArmourRate -= 0.5`) and a **Stun** poison amplifies the incoming hit ×1.5 (`DamageRate += 0.5`). Before this, monsters took player damage completely raw — 432 of 555 monsters carry real AC, so a FrostTiger/Yimoogi/FrozenWarewolf now genuinely shrugs off an under-geared character, exactly as Crystal intends. (Monsters spawned with a literal, non-manifest name carry no AC, so existing literal-named test fixtures are unaffected.)
18. **Magic spells resolve against MAC, not AC** — a player's Wizard/Taoist magic hit now mitigates against the target monster's **MAC** (`MinMAC..MaxMAC`) instead of its physical AC, faithful to Crystal's `DefenceType.MAC`. Each offensive spell was audited from the Crystal source by its damage stat — Wizard/Taoist spells deal `MinMC`/`MinSC` damage (→ MAC), warrior/assassin melee skills deal `MinDC` (→ AC), with `BladeAvalanche` the one DC-damage skill Crystal still resolves against MAC — and the classification (`crystal_spell_name_uses_magic_defence`) is threaded through the damage scheduler as a `monster_magic_defence` flag on the pending action, read by the same armour resolve as item 17. So a high-MAC / low-AC monster now shrugs off a fireball while a high-AC / low-MAC one shrugs off a sword, and vice-versa.

### Data-only long-tail port (in progress)

The 125 never-spawned families are already combat-faithful through the generated profile (distance-gated DC-melee / MC-range damage, AC/MAC armour, on-hit poison). The remaining work is their bespoke moves; that port is underway:

19. **Two-poison data-only families** — the generated profile carries a single on-hit poison, but several never-spawned families roll **two** (or three) in their Crystal `Attack()`. The pairs are now surfaced 1:1: **EvilMir** (ai 52) green + paralysis, **FinialTurtle** (72) / **OmaMage** (147) / **RhinoPriest** (137) slow + frozen, **KingGuard** (105) / **TurtleKing** (73) slow + paralysis, and **GasToad** (132) green + paralysis. A rare tertiary poison (KingGuard's green, TurtleKing's dazed) is omitted — there is no triple-poison status variant.
20. **Profile-missed on-hit poisons** — six data-only families carry a `PoisonTarget` the profile extractor skipped (it lives in `CompleteRangeAttack` or a non-standard branch), now restored 1:1: **LightTurtle** (74) green, **HellCannibal** (78) red, **FlameAssassin** (95) slow, and the Dazed trio **HellSlasher** (76) / **TrollKing** (91) / **StoningStatue** (135) via a new chance-gated `DazedPoison` status variant (the prior `Dazed` effect applied unconditionally). CharmedSnake (63) is a charmed pet, not a hostile, so it is intentionally left out.
21. **IcePillar (ai 89) bespoke boss** — its signature `Attacked`/`ApplyPoison`/`CanMove`/`CanRegen` overrides are now faithful: a **stationary, regen-less, poison-immune damage sponge** that loses exactly **1 HP per non-blocked hit** (the AC/MAC armour and agility-miss roll still apply; a landed blow then chips 1 HP regardless of rolled damage). The 1/3 struck-counterattack and the on-death frozen AoE burst remain as flavour TODOs; the damage-sponge core (what makes the pillar a pillar) is in.
22. **Stationary data-only families rooted** — ten never-spawned families override Crystal `CanMove` to false but could still chase/patrol in the runtime: **EvilMir** (52) and **EvilMirBody** (53), **Wall** (82), **TreeQueen** (142), **PowerBead** (149) and **BoulderSpirit** (170) turrets, **CaveStatue** (151), **WoodBox** (158), **FloatingRock** (166), and **PurpleFaeFlower** (212). They are now in the chase/patrol stationary gate, so they hold position and fight from their tile exactly as Crystal does (their ranged/melee combat already flows through the generated profile).
23. **Non-combatant props cannot attack or regen** — five families override Crystal `CanAttack` to false and so should never swing: **EvilMirBody** (53), **Football** (68), **Wall** (82), **CaveStatue** (151) and **BoulderSpirit** (170). They are added to `monster_can_attack`'s no-attack list; CaveStatue and BoulderSpirit additionally override `CanRegen` to false and now also skip HP regeneration (alongside the training dummy and IcePillar).
24. **Football (ai 68) kick mechanic** — the soccer-ball monster is now faithful to its `Attacked` override: a player hit deals **0 damage** and instead **rolls the ball up to 4 tiles** in the attacker's facing direction, reversing (bouncing) whenever the next tile is blocked, emitting an `ObjectPushed` per step; it never dies. Hooked at the combat resolve point ahead of the normal damage path.
25. **GlacierWarrior / MutatedManworm FindWeakerTarget blink** — these two (ai 203, 65) share SnowWolfKing's (180) exact `Attacked` mechanic: surviving a blow heavier than their own DC, they blink to a fresh (weaker) target half the time — toward the player in the single-player runtime. The existing SnowWolfKing teleport was generalised (`snow_wolf_king_teleport_to_player_with_effect`) so all three reuse it, with the correct per-monster teleport visual (king effect 11, the warriors effect 4).
26. **Sep PvP-clone defence/damage typing corrected** — auditing the ten Sep* clone families (ai 214–223) against their primary `Attack()` `DefenceType` and damage stat surfaced three generated-profile errors, now fixed: **SepHighTaoist** (221) resolves against **MAC** (its primary is `MACAgility`) — it was missing from the always-magic list; **SepHighArcher** (223) resolves against **AC** (its primary shot is `ACAgility`; only a conditional poison-buff AoE is MAC) — it was wrongly in the ranged-magic list; and both **SepTaoist** (216) / **SepHighTaoist** (221) deal **DC** primary damage (SC is only the slow poison's power), not the profile's `sc`. The clones' distinctive self-displacement flourishes (Wizard Repulsion-push, Archer BackStep-jump) remain cosmetic TODOs; their core combat (damage class, defence type, range, poison) is now faithful.
27. **Caster data-only families resolve against MAC** — extending the same `DefenceType` audit across the data-only roster caught five more families whose primary hit is magic-typed in Crystal but resolved against the player's physical AC in the runtime: **VampireSpider** (60, `MACAgility`), **FlameMage** (93) and **FlameAssassin** (95) via base `RightGuard` (`MACAgility`/`MAC`), **PowerBead** (149, `MACAgility`), and **HoodedSummoner** (211, `MAC`). All five are added to the always-magic list, so a high-MAC character now correctly shrugs off their casts.

## Genuine remaining gaps

- **Distinctive moves of the data-only long tail** — the ~100 never-spawned classes (EvilMir's body-part phases, the Flame/Oma/Horned/Furbolg/Sep PvP-clone families, …) work as basic combat monsters but their bespoke AoE patterns, summons and phase logic are not individually ported. Porting all of them is a multi-week effort with no stock-content impact (they are not placed by any respawn).
- **Magic-resist miss roll** — a magic hit now mitigates against the monster's MAC (item 18), but the *accuracy* half is still the physical agility roll Crystal uses for `MACAgility`; Crystal's `MAC` path also rolls a `MagicResist` miss chance. No monster carries `MagicResist` data in the manifest, so this miss roll is omitted (it would always pass).
- **Slow poison receipt** — a Slow poison's `MoveSpeed`/`AttackSpeed` reduction is a sub-second (+100 ms, capped 3500 ms) delta the runtime's 1-second tick cannot express, so a slowed monster is not yet visibly slower (Red and Stun, which were the other half of this gap, now resolve through the armour path — item 17).

## Note on the automated audit

A parallel Crystal-vs-Rust audit (three agents over all 87 spawned families)
surfaced candidate gaps, but ~40% were false positives on verification — e.g.
BugBagMaggot/RootSpider range (already `CRYSTAL_DATA_RANGE`), WoomaTaurus rage
duration (correct once 1 tick = 1 s is accounted for), ManectricClaw/DarkWraith
cooldowns/ranges (already approximated), Armadillo dig-out cycle (already routed
through `update_dig_out_zombie_state`), SnakeTotem/StoneTrap taunt (already
covered by friendly-summon targeting). Every finding above was re-verified
against the Crystal source before any change.

## Test-harness note (pre-existing, not introduced here)

The simulation suite must be run as CI runs it: `cargo +1.89.0 test --locked -p mir2-simulation -- --test-threads=1`. On this checkout the suite has ~70 pre-existing failures that are **flaky / order- and wall-clock-sensitive** (e.g. `current_wall_time_ms()` gating, absolute-tick-phase attack branches such as `tick % 6 == 1`, and high-level monsters dealing always-max damage that kills the low-HP default character faster than a test expects). A clean-tree run measured `833 passed; 70 failed`. Every change in this session was diffed against that baseline: the final state is `847 passed; 69 failed` — **zero** new failures, **+13** new passing tests, and one pre-existing failure repaired (`armadillo_type_one_branch_uses_three_half_dc_hits`, where the rolled hits now leave the player alive for all three strikes). Each fix is validated with deterministic, self-contained tests rather than relying on the flaky full-suite baseline.
