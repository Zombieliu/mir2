# Windows 资源包安装与首次可玩方案

本文件是下一阶段的设计与验收要求，不是已实现或已发布的功能。当前发布轮次
只更新本地文件处理引擎，游戏仍是 R17。19 分 1.646 秒来自最终更新器在
C 卷独立目录的完整签名安装（包源为本地文件映射，不含公网传输）；不是安装
速度极限，也不是其他笔记本的实测。

最大收益来自减少物理文件数量。当前125,965个安装目标仍需分别创建、验证、
提交，激活684,864ms。继续增加线程不能消除这些操作，亦可能与游戏及其他
程序争抢磁盘。现有四路上限、完整签名、回退和游戏独占保护继续保留。

## 直接读取带索引资源包

安装后保留少量不可变资源包及签名索引，不把资源包再次拆成十多万个文件。
索引记录规范资源路径、所在包、偏移、长度和原始内容哈希。发布构建离线
验证全部资源与旧版逐字节一致；安装先验证包和索引再挂载，包在客户端
生命周期内不可变。禁止任意绝对路径、重叠/越界偏移、重复大小写路径别名、
未验证包及损坏块进入资源加载。

已压缩 PNG/音频等采用包内直接定位读取；需要压缩的内容采用独立可寻址块。
避免把整个大 ZIP/GZIP 解压到内存后才能寻找一张图片。按 UI/字体、人物、
地图及地图共享依赖分组，包块初始候选32–64MiB，具体尺寸用真实更新变化量
和首次地图依赖集测定。完整内容哈希作为不可变对象名，R2/CDN继续分发。

项目目前有两条资源读取路径，不能只修其中一条：

- runtime/src/lib.rs 的 AssetPlugin 配置默认目录读取。
- platform-windows 中地图、frame_sets、字体、effects、pet_effects，以及
  client-bevy/audio 等包含直接 fs::read/read_to_string。

先增加统一只读 ResourceStore，再将两条路径接到同一已验证资源目录索引；
个人设置、存档、移动日志及快捷键持久化仍使用原来的个人文件路径，不进入包。
开发时保留目录读取，生产采用显式版本化的包目录，缺失/损坏不能静默回到
其他未经验证的目录。旧安装器/更新器不认识包布局时必须走兼容性检查，不能
只往现有白名单塞入新扩展名就宣称旧客户端可用。

## 首次可玩与完整下载分开

公共首包包含登录、字体、必要 UI、基础人物及进入游戏前必需的资源。角色
登录后还必须准备该角色实际所在地图和可见实体的依赖，新角色与已经在高级
地图的老角色不能共用“只下载新手区就放行”的判断。

地图切换前预取依赖，其余地图低优先级后台下载；下载线程不阻塞游戏主线程，
请求合并、有限并发、取消过期地图请求，界面明确显示进入当前地图仍缺哪些
资源。未知或未完成地图不能显示黑屏后继续战斗。离线时已安装完整资源的
行为保持可用，网络断开不破坏已挂载包。

## 后续更新按变化块复用

稳定分包和内容哈希让未改变的资源直接复用。大包不因单张小图改变就整体
重下；先通过块复用和独立包更新验证收益，再决定是否增加 EXE 二进制差分。
差分失败可回退到完整已签名对象，不能提高差分复杂度后省略最终整体验证。

提交新包和签名目录后最后切换版本指针；正在使用的旧包保留到安全回收点。
安装中断、断电、哈希失败及首次启动失败都恢复原版本。新的目录格式要显式
版本化，配套客户端/更新器/安装器需要同一 Candidate 验证和分阶段发布。

## 下载线路与限速识别

本轮 Linux CI 对817,841,942个公开字节全量核验，累计公开读取47.724秒；
本开发电脑对其中一个60,629,129字节包读取426.237秒。不同节点/时段的结果
不能互相比作同一条件提速；它们说明 R2 已发布，并不能代表每条玩家线路快。

下载器要保留真实速率、已完成字节和剩余量，分别计时 DNS/TLS、首字节和
持续传输。对固定已授权下载源进行小范围测速和有限并发比较，慢线切换/续传
仍绑定同一个签名对象的完整哈希；跨来源时不能直接信任另一站的 ETag 或
把不匹配的分段拼接。持续慢速不能永远等到“完全没数据”才触发换线，但
阈值、探测流量和并发上限需通过网络对照确定。可用资源包减少首包等待量，
不能消除线路带宽限制。新增第三方镜像/计费服务不在当前发布范围。

## 验收

以下是工程目标，不是已经测得的时间或对用户网速的承诺：

- 同机、同盘、完整资源、相同冷缓存条件做反向对照；本地部署阶段目标降低
  至少90%，分别记录校验、暂存、提交和总墙钟，不把后台下载计时隐藏。
- 单独报告首次可玩和完整资源就绪时间；联网传输与本地磁盘处理分别计时。
- 全资源离线逐字节相同；九语言字体、职业动画、地图对象和音效缺失计数为零。
- 新角色与已在高级地图角色都可启动、换图、断线恢复；下载中移动/战斗的帧
  时间不得劣于原版对照，队列取消和内存上限有实际记录。
- 旧客户端升级、完整首装、中断续传、缓存损坏、签名错误、失败回退、游戏
  正在运行时的保护全部通过后，才能切换公开 feed。

实现顺序：离线资源清单及分包实验 → ResourceStore与两条读取路径 → 生产
签名目录/更新器事务 → 首次可玩依赖调度 → Windows真实安装与跑图对照 →
分阶段发布。每一步保留可用的旧版回退，而不是同时替换所有组件后才验收。
