# Asset Release Runbook

This runbook separates browser-facing assets from server-side Gateway assets.

## Current Split

Player Web assets:

- generated `original-ui`, `original-map`, audio, and Bevy runtime files are
  staged from `apps/web/public`;
- the remote release manifest is generated by
  `apps/web/scripts/build-remote-asset-release.mjs`;
- uploads go to Cloudflare R2 through
  `apps/web/scripts/upload-r2-assets.mjs`;
- the Web app discovers the active base URL through `/api/asset-manifest`.

Gateway assets:

- the Gateway binary carries gameplay data from `packages/game-data`;
- full Crystal collision lookup uses `CRYSTAL_CLIENT_ROOT/Map/*.map`;
- map files are released separately with
  `scripts/package-crystal-map-assets.sh`.

## Web Asset R2 Release

Player Web asset releases are versioned by `MIR2_ASSET_VERSION`. In CI this is
the short GitHub SHA (`${GITHUB_SHA::12}`); locally set it explicitly and use
the same value for the R2 upload, Cloudflare Worker proxy, and Vercel build.
The current verified public R2 release base is:

```text
https://assets.mir2.obelisk.build/mir2/v/<asset-version>
```

For local refresh, start Player Web, stage the release, and upload:

```bash
cd apps/web
MIR2_ASSET_VERSION=<asset-version> \
NEXT_PUBLIC_MIR2_ASSET_BASE_URL="https://assets.mir2.obelisk.build/mir2/v/<asset-version>" \
MIR2_ASSET_OBJECT_PREFIX="mir2/v/<asset-version>" \
npm run build
npm run start -- --hostname 127.0.0.1 --port 13020
```

In another shell:

```bash
cd apps/web
MIR2_ASSET_VERSION=<asset-version> \
NEXT_PUBLIC_MIR2_ASSET_BASE_URL="https://assets.mir2.obelisk.build/mir2/v/<asset-version>" \
MIR2_ASSET_OBJECT_PREFIX="mir2/v/<asset-version>" \
npm run assets:remote:build -- \
  --baseUrl http://127.0.0.1:13020 \
  --assetBaseUrl "https://assets.mir2.obelisk.build/mir2/v/<asset-version>" \
  --objectPrefix "mir2/v/<asset-version>"

MIR2_R2_BUCKET=mir2-web3-assets npm run assets:r2:dry-run
MIR2_R2_BUCKET=mir2-web3-assets \
MIR2_R2_VERIFY_ORIGINAL_ASSETS=1 \
npm run assets:r2:upload
```

Release order is strict:

1. Generate original assets and `public/original-asset-manifest.generated.json`.
2. Build the remote asset release under `mir2/v/$MIR2_ASSET_VERSION`.
3. Upload that release to R2.
4. HEAD-verify every manifest-declared original asset on the final CDN URL.
5. Deploy the `mir2-domain-proxy` Worker with the same `MIR2_ASSET_VERSION`.
6. Deploy Vercel with the same `MIR2_ASSET_VERSION`,
   `NEXT_PUBLIC_MIR2_ASSET_BASE_URL`, and `MIR2_ASSET_OBJECT_PREFIX`.

Do not deploy Vercel before the R2 prefix and Worker proxy are verified.

Do not deploy Vercel alone for production.
`web-assets-r2-release` must run with:

- `publish_r2=true`
- `deploy_worker=true`
- `deploy_vercel=true`

Do not manually deploy `mir2-domain-proxy` unless both
`MIR2_ASSET_VERSION` and `MIR2_ASSET_OBJECT_PREFIX` are explicit and
consistent with `/api/asset-manifest`.

For targeted full-library repairs without expanding the main checkout, export
one Crystal UI library into a temporary staging root and upload a focused
release manifest:

```bash
CRYSTAL_CLIENT_ROOT=/Users/henryliu/obelisk/ai/numeron/mir2/downloads/crystal-client-full \
node apps/web/scripts/export-crystal-ui.mjs \
  --libraries Items \
  --fullLibraries Items \
  --outputDir /tmp/mir2-original-ui-full
```

The authenticated bulk-upload Worker is also routed at
`assets.mir2.obelisk.build/upload*` for publishing many small files without
spawning one Wrangler process per object. Use
`MIR2_R2_UPLOAD_DRIVER=worker`, `MIR2_R2_UPLOAD_WORKER_URL=https://assets.mir2.obelisk.build`,
and a freshly deployed `MIR2_R2_UPLOAD_SECRET` when uploading focused repair
manifests.

When repairing static original UI coverage, include both the PNG/WAV/CUR
objects and their metadata. Uploading every local `original-ui/**/meta.json`
plus `manifest.generated.json`, `source-libraries.generated.json`, and
`sound-index.generated.json` lets `/api/original-ui-meta?library=...` hit the
player-domain proxy's R2 metadata path before falling back to the Vercel API.
The Vercel API route is read-only for deployed metadata; it must not perform
request-time Crystal export in production. If a library returns
`library_not_deployed`, generate it locally with the export scripts or publish a
focused R2 repair before redeploying or retesting.

The production asset domain is served by `infra/cloudflare/mir2-r2-asset-cache`
on route `assets.mir2.obelisk.build/*`. The player domain is served by
`infra/cloudflare/mir2-domain-proxy`; it now serves same-origin asset paths
directly from the same R2 bucket:

```text
https://mir2.obelisk.build/original-map/...              -> mir2/v/$MIR2_ASSET_VERSION/original-map/...
https://mir2.obelisk.build/original-ui/...               -> mir2/v/$MIR2_ASSET_VERSION/original-ui/...
https://mir2.obelisk.build/generated/original-map-blend/... -> mir2/v/$MIR2_ASSET_VERSION/generated/original-map-blend/...
```

Keep both Workers deployed unless an equivalent Cloudflare Cache Rule is
installed, because the raw R2 custom domain can otherwise report
`cf-cache-status: DYNAMIC` even with immutable object headers. Same-origin
Bevy `/original-ui/...` asset requests depend on the player-domain Worker
route, not on React image fallback.

Player Web should only remote-fetch `/original-ui/...` and `/original-map/...`
plus generated map blend paths through this R2 base. Keep `/bevy-runtime/...`
same-origin with short cache headers so the wasm-bindgen JS/WASM pair always
comes from the same Vercel deployment.

## CDN-First Vercel Output

Production Player Web deploys should not upload the large Crystal media tree to
Vercel once the same paths are verified through the player-domain R2/CDN route.
Use the prebuilt flow from `apps/web`:

```bash
MIR2_ASSET_VERSION=<asset-version> \
NEXT_PUBLIC_MIR2_ASSET_BASE_URL=https://assets.mir2.obelisk.build/mir2/v/<asset-version> \
MIR2_ASSET_OBJECT_PREFIX=mir2/v/<asset-version> \
NEXT_PUBLIC_MIR2_GATEWAY_WS_URL=wss://mir2.obelisk.build/ws \
npm run vercel:build:prod -- \
  --report ../../docs/generated/remote-assets/vercel-output-prune-resource-cdn-first-$(date +%Y%m%d).json

npm run vercel:deploy:prod
```

`vercel:build:prod` runs `vercel build --prod --yes` and then
`apps/web/scripts/prune-vercel-output-assets.mjs`. The prune script only
deletes generated files under `.vercel/output` and only for paths that are
served by R2/CDN:

- `static/original-ui`
- `static/original-map`
- `static/generated/original-map-blend`

Do not prune source files in `apps/web/public`; local development,
asset export, and metadata repair flows still use that tree. Do not prune
`static/debug` until the player page and smoke reports prove that the debug map
samples are no longer requested. On 2026-05-21, pruning `static/debug` caused
playable production smoke to report 404s for
`/debug/map-samples/smtile-72.png` and `smtile-80.png`, so the production-safe
script now retains it.

After deploy, verify both the CDN-backed asset routes and the playable path:

```bash
MIR2_WEB_BASE_URL=https://mir2.obelisk.build \
npm run smoke:production-original-assets

MIR2_WEB_BASE_URL=https://mir2.obelisk.build \
npm run smoke:cache-maintenance -- \
  --runId resource-cdn-first-final-prod-$(date +%Y%m%d) \
  --waitTimeoutMs 180000

MIR2_WEB_BASE_URL=https://mir2.obelisk.build \
MIR2_GATEWAY_WS_URL=wss://mir2.obelisk.build/ws \
npm run smoke:playable-metrics -- \
  --runId resource-cdn-first-playable-final-prod-$(date +%Y%m%d) \
  --waitTimeoutMs 300000 \
  --account demo \
  --password demo
```

The 2026-05-21 accepted CDN-first deployment
`dpl_ieQqdaZMnnZYNe4wxksuoqsj7Sgg` reduced `.vercel/output` from
420,957,251 bytes / 18,650 files to 43,478,680 bytes / 278 files and uploaded
15.7MB through `vercel deploy --prebuilt --prod --archive=tgz --yes`.

## Browser Cache Tiers

Player Web does not prewarm one undifferentiated static asset cache. Resource
packs in `apps/web/lib/asset-cache-packs.ts` should declare `cacheTier`:

- `critical`: login shell, character select, and core HUD assets needed before
  or during early play.
- `background`: map/scene frame packs that can be warmed after the critical
  path.

`/api/asset-manifest` publishes separate runtime budgets for
`staticCriticalMaxEntries`, `staticBackgroundMaxEntries`, and
`staticRuntimeMaxEntries`. The asset Service Worker writes tiered requests to
versioned buckets named `mir2-asset-cache-static-critical-*`,
`mir2-asset-cache-static-background-*`, or
`mir2-asset-cache-static-runtime-*`; scene prewarm sends best-effort tier hints
so dynamically discovered frame URLs land in the intended bucket. The cache
maintenance smoke should show separate critical/background buckets before this
is treated as a production-ready resource-management change.

The Cloudflare player-domain proxy should also route
`/generated/original-map-blend/...` to the asset origin. Those small generated
PNG frames are produced from source map sprite blend rules, and routing them to
R2 avoids a cold first-load dependency on Vercel for the same URLs.

Disable Cloudflare Rocket Loader for `mir2.obelisk.build/*` at the domain
settings level until hydration behavior is fully verified. This is a temporary
hardening step to remove JS scheduling side effects during smoke verification.
As a secondary hardening layer, `OriginalClientShell` is rendered only on
client-side (no SSR mount).

The manual workflow `Mir2 Web Assets R2 Release` performs the same staging and
upload flow in GitHub Actions when the generated static assets are present in
the checkout.

Required GitHub secrets for publishing:

```text
CLOUDFLARE_API_TOKEN
CLOUDFLARE_ACCOUNT_ID
MIR2_R2_ASSET_BUCKET
```

Optional secret:

```text
MIR2_PUBLIC_R2_ASSET_BASE_URL
```

## Vercel Wiring

Set these Vercel env vars before handing the URL to testers:

```text
NEXT_PUBLIC_MIR2_ASSET_BASE_URL=https://assets.mir2.obelisk.build/mir2/v/<asset-version>
MIR2_ASSET_OBJECT_PREFIX=mir2/v/<asset-version>
NEXT_PUBLIC_MIR2_GATEWAY_WS_URL=wss://<gateway-domain>/ws
MIR2_PASSKEY_AUTH_SECRET=<same-secret-as-gateway>
MIR2_ENV=staging
```

`NEXT_PUBLIC_MIR2_ASSET_BASE_URL` should match the uploaded `MIR2_ASSET_VERSION`
prefix in the same release cycle. Avoid pointing the app at a fresh
`{version}` prefix before it is uploaded and smoke-verified.

## SoundList Fallbacks

The latest asset smoke has no missing remote-release files and no missing
SoundList ids. The current Crystal source tree does not contain exact upstream
files for these SoundList names, so the Web exporter publishes explicit
fallback WAVs under the expected original paths:

```text
10022 -> 22.wav           fallback source: 23.wav
10109 -> 109.wav          fallback source: 110.wav
705   -> ZombieRevive.wav fallback source: 64.wav
```

`sound-index.generated.json` marks those entries with `fallback=true`,
`exactSourceExists=false`, `fallbackSourceFileName`, and `fallbackReason`. If the
exact upstream files become available, place them in `CRYSTAL_CLIENT_ROOT/Sound`
and rerun:

```bash
CRYSTAL_CLIENT_ROOT=/Users/henryliu/obelisk/ai/numeron/mir2/downloads/crystal-client-full \
npm --prefix apps/web run export:crystal-sounds

node apps/web/scripts/smoke-crystal-assets.mjs
```
