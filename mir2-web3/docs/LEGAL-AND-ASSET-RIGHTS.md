# Legal And Asset Rights

本文记录开发交接中的授权边界和待确认事项，不构成法律意见。公开发布、商业运营或向新的组织分发代码和素材前，应由项目所有者及具备相应司法辖区资质的专业人士确认。

## 当前状态

- 截至 2026-07-22，根仓库和 Crystal 子模块没有可识别的根 `LICENSE`、`COPYING` 或 `NOTICE` 文件。
- 同日 GitHub 元数据显示 `Zombieliu/mir2` 为私有，而 `Zombieliu/Crystal` 为公开。公开可见只说明技术上可读取，不会自动产生开源许可、复制权或再分发权。
- 因此，仓库访问权限不应被解释为自动获得开源许可、再许可权或公开分发权。
- 私有 GitHub Release 只解决受控下载与完整性校验，不证明其中素材可以公开或商业分发。
- `generated/crystal-packs/full` 是从 Crystal 客户端数据生成的派生图集。格式转换不会消除原始素材的权利限制。

## 内容来源与处理规则

| 内容类别 | 当前交付方式 | 接手规则 |
| --- | --- | --- |
| 本仓库自研代码 | 私有 Git 仓库 | 由项目所有者以书面方式明确开发、复制、修改和部署权限 |
| Crystal 参考源码 | 固定提交的 Git 子模块；当前 fork 公开可读 | 先确认上游条款和公开镜像依据；没有依据时由所有者收紧 fork 可见性，不因当前公开状态推定许可 |
| Wemade / Legend of Mir 2 名称、图像、声音及客户端数据 | 私有素材 Release 或维护者本地原始数据 | 未完成权利确认前不得公开、出售、再许可或上传到公开 CDN |
| 生成的 Atlas、manifest 和转换数据 | Git 中的允许子集或私有素材包 | 按其原始输入的限制处理，不因转换而视为自由素材 |
| npm、Cargo 和其他第三方依赖 | 锁文件固定版本 | 发布前生成并审查第三方许可证清单和 notices |

## 新开发者授权清单

项目所有者在邀请外部开发者前应完成以下记录：

1. 确认开发者所属主体、工作范围、开始和结束日期。
2. 用合同、保密协议或其他书面文件明确代码及素材的访问、修改、复制和交付范围。
3. 记录 `Zombieliu/Crystal` 公开 fork 的授权依据；无法确认时，在交接前由仓库所有者将其改为私有或停止分发，不把技术可见性当成法律依据。
4. 只授予私有仓库和必要 Release 的最小权限，不共享个人 access token、R2 密钥或生产凭据。
5. 确认开发者不得把原始 `.Lib`、客户端安装包、完整图集或仓库镜像转交第三方。
6. 访问结束后撤销 GitHub、对象存储、CI 和测试环境权限。
7. 在项目自己的安全记录中保存批准人、依据、日期和撤权结果，不把合同或个人信息提交到本仓库。

## 公开或商业发布前

- 确认项目自研代码采用何种许可证或商业授权条款，并由有权主体正式添加，而不是由开发者推测。
- 取得 Crystal/Wemade 相关代码、素材、商标、名称、声音和衍生内容的明确使用与分发依据。
- 为目标市场确认知识产权、商标、消费者、隐私、支付、未成年人和内容分级要求。
- 巴西上线计划应由熟悉巴西市场的专业人士审查，技术团队不能把私有开发环境可运行当作商业发行批准。
- 决定素材 CDN 的鉴权、地域、缓存撤销和下架流程后，再发布 R2 或其他公开对象存储版本。

## 发生不确定性时

暂停扩大访问范围，保持仓库、Release 和对象存储为私有，记录待确认的素材来源与用途。不要用删除来源信息、重命名文件或再次转换格式来规避权利审查。
