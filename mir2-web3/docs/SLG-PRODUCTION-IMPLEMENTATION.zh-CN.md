更新日期：2026-10-08。首批实现是可组合制作的同步 Rust 规则模块；正式玩家入口尚未开放。

代码位于 [`packages/production`](../packages/production/README.md)，已加入工作区，并由 `mir2_simulation::production` 导出。原版 NPC 即时合成和武器精炼继续使用原流程。本批没有启动游戏、重启网关、修改角色资产或替换安装包。

## 已完成的基础代码

| 内容 | 当前行为 |
| --- | --- |
| 可组合配方 | 读取 v0.2 目录；检查材料、生产来源、循环、数值范围及唯一产出 |
| 全链开放条件 | 递归核对原料来源、上游设施、解锁条件和真实物品模板绑定；缺少一环就拒绝开工 |
| 缺料计划 | 优先计算现有中间材料，展开缺少的上游批次，显示原料缺口、余料、工费和顺序工期；不自动扣整条链 |
| 一至十份批量 | 校验 UID、数量、模板和可用实例；生成真实实例扣料计划，保留原始物品载体 |
| 离线工期 | 记录服务器开始/完成时间；恢复后沿用原时间，旧任务冻结成本、产量和配方内容 |
| 领取与取消 | 到期后生成整批交付计划；提前取消按每种直接投入总量返还一半并向下取整，工费不退 |
| 绑定材料 | 任一绑定投入使成品绑定；退款优先保留绑定投入的原始来源，不能返还成上游原矿 |
| 请求重试 | 同一角色和请求 ID 的完全相同请求返回旧结果；更改配方、数量或操作则拒绝 |
| 保存恢复 | 验证配方身份、内容摘要、任务身份、投入数量、状态历史和每台设施的未结束任务 |
| 容量边界 | 编码记录上限 16 MiB；开工前为未结束任务预留最大领取/取消回执空间；历史记录不静默丢弃 |

这里的“扣料计划”和“交付计划”是交给真实经济事务的方案。返回方案不表示已经扣款、保存成功或发货。账本版本和背包版本必须一起核对，物品、金币、任务与回执必须一起持久提交，之后才能更新 World 和发送成功包。

## 后续落地顺序

1. 个人经济接线：使用已有的不可复用角色身份和账号提交事务，校验真实 ItemState 的模板、数量、纯度、绑定及保护属性。整批空间/重量检查、全球 UID 分配、扣料、扣费、保存任务和领取入包必须原子提交；提交结果不明时查询原操作。
2. 正常来源：逐项加入真实木材、纤维、石料、作物及材料目录，接采集和种植；保留普通矿石白名单，保护黑铁、金矿、高纯度及精炼物品。新符号 ID 不能直接当游戏物品。
3. 共用作坊与界面：比奇、盟重的基础加工台、窑炉、厨房；检查位置、距离、当前操作权限，提供材料来源、缺料、工期、领取和取消显示。
4. 首个闭环：材料 → 中间加工 → 组合建材 → 实际建筑；种植 → 药品包 → 原版用药。随后接食品效果、正常钓鱼和专用盐矿。
5. 行会工坊：领地持有任务，使用共享仓库与预算事务，并独立检查启动、取消、领取权限；不能借个人 Session 保存公共资产。历史归档须保留重放与资产保管，避免长期生产达到记录上限。
6. 联网验收：普通角色获取材料、生产、离线重登、领取、满包、两个会话争抢、取消/完工竞争、权限变化与三职业、多语言界面。通过后才开启相关配方并发布可玩版本。

当前内置目录仍为 `productionEnabled=false`，所有新材料的 `runtimeTemplateId` 仍未绑定。采集、种植、建造、食品和公共工坊没有因此变成已完成；本批也不增加原版 1:1 parity 的验收比例。
