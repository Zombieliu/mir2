没有启用录像、AI、裁片或平台投稿，也没有重启游戏网关。

`clipExport` 目前发送的是事件/文案内容包，不是MP4。内容包只有可选语音地址、
观战链接、地图、镜头目标、帧序号等字段，没有视频文件、已生成裁片或投稿结果。
现有适配器收到 HTTP 2xx 只记录投递成功，不能据此认定视频生成或B站投稿成功。

当前公开观战是约3秒延迟、网页近期交战选镜头；真正的 Boss/PK 权威事件投影、
视频循环录制、事件与视频时间轴对齐仍未完成。观战JSON快照不能充当可直接投稿的视频。

## 官方接入条件

开放平台公开列出视频发布、删除、查询能力；视频稿件能力使用 `ARC_BASE`，
需要应用权限和用户授权。请求使用应用凭据、OAuth访问令牌和官方签名。
这是独立于直播姬登录及RTMP推流配置的接入。

- [开放平台入口与入驻流程](https://open.bilibili.com/)
- [官方视频管理文档入口](https://openhome.bilibili.com/doc)
- [稿件权限说明（ARC_BASE）](https://open.bilibili.com/doc/4/ddfbe54d-b4ab-340e-c698-933b9a3c619c)
- [官方请求签名与错误码](https://open.bilibili.com/doc/4/8673959e-f7bb-56e6-6e68-d225f971b81b)
- [查询用户已授权权限；该接口自身需要USER_INFO](https://open.bilibili.com/doc/4/08f935c5-29f1-e646-85a3-0b11c2830558)

本轮可确认官方站点HTTP入口可达；页面动态加载，正文检索参考公开索引。
没有以测试请求碰撞用户应用权限，也没有调用真实投稿、删除或编辑接口。
准确上传协议、配额和可用能力应在获批应用的官方后台再次核对，不把第三方逆向接口
或直播码作为开放平台授权。

## 审核期间可独立建设的部分（设计，尚未实现）

1. 在播出电脑或独立视频机器建立有界循环录制，保存完整画面与声音，限制磁盘占用。
2. 将公开可用的真实事件、观战帧时间和视频PTS关联，补偿约3秒观战延迟；
   不把网页附近怪物评分冒充Boss击杀或PK证据。
3. 裁取事件前15秒、后30秒，合并重叠窗口，生成横版MP4；竖版保留战斗画面和关键HUD。
4. 保存视频校验值、内容ID、封面/标题和生产状态，形成可人工检查的待投稿队列。
5. 裁片适配器持久化并去重任务后才回应已接收；视频完成、上传完成、稿件提交和
   审核通过必须分别记录，不能复用现有“HTTP投递成功”计数表示全部成功。

游戏Gateway只投递脱敏事件，录制和编码不进入玩家请求路径。

## 权限获批后的接入顺序（尚未执行）

1. 在开放平台确认应用的稿件能力获批、回调地址及调用范围。
2. UP主本人完成一次账号授权；后端保存凭据，按官方流程处理续期、撤销和失效。
3. 按获批应用文档实现封面/视频上传、稿件提交及状态查询，把返回的稿件ID保存到队列。
4. 使用一条已验收的实际MP4完成首轮投稿；分别确认接口结果、审核状态和B站观看端画面/声音。
5. 首轮通过后再启用获授权的自动投稿规则、频率和失败恢复；提交结果不确定时先核对稿件状态，
   避免盲目重试造成重复投稿。

当前需要用户处理的是等待投稿权限审核；审核通过后再进行账号授权。
当前没有要求在聊天中提供密钥，也没有把尚未开通的API标记为可用。
