## 冲突处理与边界

- PostgreSQL 迁移使用完整字符串 ID。保留后端原 28 条的顺序，再追加容量 5 条，合计
  33 条；数字前缀相同不是主键冲突。不改已部署 SQL、不重编号。AccountStore schema 仍为 14。
- 普通商店 Credit 扣款显式消费 FIFO 来源，覆盖“未保存奖励增加后立即消费、最终余额不变”。
  不调整价格、充值比例或经济数值。
- 跨分支 PG 夹具改用正式迁移器并记录版本，验证二次初始化；public Zone lease 不允许被
  局部同名表替代。击杀测试保留 SourceOfTruth 事实/回滚/重登证明，Mirror 明确拒绝 PG
  权威写入；另验证普通 File 本地击杀仍可正常增加经验。
- 官网推广登录刷新接入客户端已有身份租约、连接代次与预认证门禁；正常登录和推广认证
  配置独立。Windows 默认及显式 legacy 活动继续使用不同后端、Cookie、密钥域和账本。
- 保留经过版本/工件校验的 Bevy 本地代理，避免旧官网配置恢复无条件 rewrite。
- `.github/workflows/web-assets-r2-release.yml` 保留原客户端/资产发布能力；推广发布独立在
  `promotion-website-release.yml`，仍为手动触发。发布脚本只接受统一分支与不可变 SHA，
  原部署 baseline 保持失败关闭；发布前必须重新只读核对。旧 unified/realtime 的 legacy
  活动验收合同属于历史合同，不可直接用来发布当前 Windows 默认活动。
- 两个站点的 `vercel.json` 对统一分支设置 `git.deploymentEnabled: false`，源码推送与手动
  发布分离，其他分支配置不变。配置语义依照
  [Vercel 官方 Git 配置](https://vercel.com/docs/project-configuration/git-configuration)。
  连接器的项目摘要未提供 Git/忽略构建设置，未借此假定自动部署已关闭；也未修改远程配置。
- Windows 推广发布守卫同时要求后端 `monthly_purchase_full` 与前端对应文案/标记。
- 原目录独有 payout/sign/proxy 是显式调用的离线/运维工具，不接入正常发布流程。
  `promotion-playtest-proxy.mjs` 仅用于历史 legacy 本地开发，缺少新的赛季、billing 与
  game-session 转发合同，不得当成统一公网入口。
- `infra/cloudflare/mir2-full-installer-downloads` 保留安装包分片下载与受限导入的未完成源码。
  本轮仅离线测试；未执行 R2 写入、Worker 部署、URL 切换或下载加速验收。
