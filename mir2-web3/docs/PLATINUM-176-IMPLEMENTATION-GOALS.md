# 白金 1.76 完整实现 Goal

> 状态：Execution Plan v0.2（执行中）
>
> 对应产品方案：`docs/PLATINUM-176-PRODUCT-LOOP.md`
>
> 总目标：在不破坏 Crystal 全量原始数据的前提下，以 `platinum_176` 内容 Profile 交付战士、法师、道士从 1 级自然成长至 50 级的完整游戏循环，并完成经济、Boss、PK、行会、沙巴克、持久化、资产、运维和发布验收。
>
> 完成定义：不是“地图能打开”或“GM 能调到 50 级”，而是三个职业都能通过正常击杀、掉落、学习、装备、交易和社交玩法到达 50 级；服务器重启、断线重连和持续运行后数据仍正确。

## 0. 执行原则

### 0.1 版本边界

- [ ] 只开放战士、法师、道士。
- [ ] 本期自然成长验收边界为 1–50 级。
- [ ] 50 级不是代码硬上限，50 级以上仅不属于本期内容承诺。
- [ ] 排除英雄、内功、心法、转生、刺客、弓手和 1.76 后的主成长系统。
- [ ] 不出售经验、装备、金币、技能书、掉率或传送优势。
- [ ] 不以任务直升、签到或后台赠送代替世界产出。
- [ ] 原始 Crystal manifest 只读；所有白金服选择和修正进入独立 Profile。

### 0.2 工程完成标准

每个 Goal 同时满足以下五条才可标记完成：

1. **规则已实现**：服务器权威逻辑存在，不依赖前端自觉。
2. **数据已配置**：地图、怪物、物品、技能和数值来源可追溯。
3. **玩家可体验**：正常客户端路径可触达，不需要 GM 命令。
4. **自动化可证明**：有测试、探针或可重复脚本。
5. **证据已归档**：保留最终报告，不堆积无价值的中间截图和日志。

### 0.3 环境总决策

**Mac 是主开发机，Windows 是共享 Staging、兼容性和原版参考机。不要整体迁回 Windows。**

| 工作 | Mac | Windows / WSL2 |
|---|---|---|
| 日常编码、重构、单元测试 | 主责 | 可选 |
| Rust 服务端、Next.js、Bevy WASM | 主责 | 回归 |
| Profile、数据编译、自动化脚本 | 主责 | 复验 |
| 本地 Crystal 资产导出 | 主责，能跑则保持 | Windows-only 工具兜底 |
| Postgres/Redis/NATS/Redpanda/ClickHouse | 本地轻量开发 | 长期共享 Staging |
| 双客户端联机、断线重连、长时运行 | 快速验证 | 主责 |
| Windows 浏览器/WebView/Tauri | 不负责最终结论 | 主责 |
| 原版 Crystal 客户端/服务端对照 | 不强求 | 主责 |
| 性能与 GPU 真机验收 | Safari/Chrome/macOS | Edge/Chrome/Windows |
| 发布前候选版本 | 构建、测试、签名准备 | 部署、兼容性、冒烟 |

### 0.4 机器切换规则

- 日常分支和源代码以 Git 为唯一同步源，不手工复制仓库目录。
- 数据库迁移先在 Mac 临时库验证，再进入 Windows Staging。
- Windows Staging 的数据库是共享测试数据源，不作为生产数据库。
- Windows 仓库放在 WSL2 Linux 文件系统，例如 `~/mir2-web3`，不放在 `/mnt/c/...`。
- 原始 Crystal 客户端资产不进 Git；两台机器通过各自的 `CRYSTAL_CLIENT_ROOT` 指向本地合法来源。
- 每个阶段结束才做一次完整 Windows Gate；不为每个小改动切换机器。

| P6 产品化 | G16–G17、G19–G21 | 10–20 天工程 + 2 小时集中封测 | 发布候选 |

### 总工期判断

- **可内部完整跑通 1–50**：约 5–8 周。
- **包含 PK、行会、沙巴克和经济闭环的封闭 Alpha**：约 8–12 周。
- **经过 20–50 人 2 小时集中封测、2 小时稳定性和两轮平衡后的可公开候选版本**：约 10–14 周。
- 若关键技能、怪物 AI、交易事务、沙巴克或资产链实际尚未实现，取区间上沿。
- 若由 2–3 名熟悉 Rust/游戏服务端的工程师并行，工程时间可缩短，但平衡与封测的日历时间不会同比缩短。

## 2. 每周执行节奏

### 每日 Mac Loop

1. 选择一个最小可验收工作项。
2. 先补失败测试或探针。
3. 实现服务器权威逻辑。
4. 补 Profile 数据和客户端反馈。
5. 跑受影响单测、集成测试和短程游戏探针。
6. 只保留最终验收报告。
7. 提交范围清晰的 commit。

### 每阶段 Windows Gate

1. 拉取锁定 commit。
2. 在 WSL2 重新构建，不复用 Mac 产物。
3. 迁移独立 Staging 数据库。
4. 运行两个以上真实客户端。
5. 验证断线、重连、重启、交易、组队和切图。
6. 运行本阶段三职业加速路线。
7. 归档结果和性能指标。
8. Gate 通过后才进入下一等级段。

### 每周产品审阅

- 经验节奏是否仍符合阶段目标。
- 金币产销是否开始失衡。
- 三职业是否出现唯一最优解。
- 稀有技能书和装备是否过量或断供。
- 玩家是否被迫重复单一地图。
- 本周新增内容是否引入版本外功能。
- P0/P1 问题是否阻塞下一 Gate。
