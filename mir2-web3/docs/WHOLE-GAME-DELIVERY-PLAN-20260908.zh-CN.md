# 全游戏完整度落地计划

日期：2026-09-08。状态：计划已建立，阶段验收尚未执行。

## 目标与范围

以 Crystal 源码与原始内容为基准，补齐整个游戏的普通玩家流程、共享世界规则、内容和 Windows 操作体验，形成同版本可复验的 Candidate，再进行最终人工玩法/视觉验收。

Windows 是当前主验收端；共享协议或服务端变化同步检查 Web，不能用 Web 通过替代 Windows 通过。Android 延续既有独立交接范围，不在本计划中自动启动。

基线为 [36 领域审计](generated/whole-game-audit-20260908/domains.csv)、[完整审计报告](WHOLE-GAME-COMPLETENESS-AUDIT-20260908.zh-CN.md)及后续修复记录。审计快照不覆盖重写：市场/精炼材料实例保管、精炼炉目标/计时修复已取得定向自动化证据，但全服市场、精炼随机/重启计时和 Windows 新包仍未完成。

不以任务数、模板数、函数数或历史测试总数计算全游戏百分比。先建立行为目录，区分“待核查、确认缺失、已实现、自动化通过、同版实机通过、人工接受、外部阻塞”；阻塞和降级不能从分母中悄悄删除。

## 后续批次拆分规则

- 任务：按前置/分支、职业等级、次数重置、击杀、道具、交付、选择奖励、放弃与失败、持久化分类；建立154项任务ID到能力与测试映射。首条链通过后再扩展，不能靠一条新手链宣称全部任务完成。
- 技能与状态：按技能×等级边界×目标类型×距离/安全区×成功/失败×资源消耗×时序/恢复记录；109模板、59 Buff 是导入基线，不是行为验收数量。
- 怪物：建立源专属行为→个人执行路径→Zone 执行路径→客户端资源映射，优先普通怪，再具有传送/阶段/召唤机制的 Boss；每族独立验证。
- 经济：先盘点每种资产持有者与转移点，再补入口和规则；失败、重放、重登、满包、未知保存结果必须保留可恢复权威，禁止按模板补造旧实例。
- NPC/地图：生成源语法与处理器差集，逐一处理定时器、实例移动、邮件等遗漏；补通用地图事件与矿区后验证真实普通服务路径。
- 社交：先明确共享服务所有者，再实现多账号一致性和 UI。行会、市场、攻城分别拆开，不在一个回合重写。

## 工程与验收约束

遵守 AGENT-ORCHESTRATION.md：协调者负责集成，高冲突文件每轮只有一个代码写者；探索角色只读，审查/QA 可与不冲突工作并行。此计划不自动切换模型或新建任务。模型可用性以实际工具支持为准，账号安全、迁移及跨分支集成由 frontier 模型领导与复核。

个人 SimulationSession 管鉴权、选角、个人资产和保存；共享 Zone/领域服务管多人权威世界。禁止向普通客户端开放 MoveTo、Stage5Command、QA/admin 命令或裸 account_id 登录。不得为补专属怪物行为回退到每会话独立世界。

每个任务绑定：原版依据、当前缺口、写入范围、测试、正常玩家入口、输出证据、已知限制和下一项依赖。服务器变化更新 roadmap/progress/parity；前端变化在截图/测试后更新玩家 QA/前端差距表。保留既有修改、历史失败和历史通过的版本边界。

在源码、自动化、同版实机三个维度分别报告进展。未完成语义分母前仅报告任务/行为通过数量，不给总完整度百分比。不承诺未经测量的总工期；M0/M1 完成后依据缺陷数、修复用时和待验行为量更新排期。
