## 必须保留的合同

- 原生登录保留账号密码与 Dubhe Wallet 入口；扫码消息必须带经验证的 token，不能放开裸账号登录。
- 十语言索引、完整简体字体、873 条精确校订和参数保护保持；钱包新增词条也进入简体生成流程。
- 个人求购、链下托管、链上确认和游戏交付状态保持；不把金币、点券或装备改成链上货币/NFT。
- 法币、测试网 USDC 和月卡分开；旧订单恢复、幂等、账号作用域及晚回调隔离保持。
- 合并 schema 13 与旧 schema 兼容规则，保留双方迁移身份及防抹账/唯一约束，不对真实数据库直接做试验。
- Zone 共享权威、最终位置保存、AOI 和战斗确认规则保持，不以每个个人会话模拟其他玩家。
- 资源包直接读取及健康确认不能因集成回退；完整性、防降级、签名、未知版本拒绝和回滚规则保持。

## 更新序列与发布门禁

检查时公网五职业频道仍为 `sequence=24` 的 `wallet-28`；r10 的已签 seed 为
`2026102910`，所以旧 r10 会拒绝该公网序列。资源包候选 `31` 也低于此 floor。
不能通过删除本地 floor、关闭防降级，或为旧游戏简单抬高共享 feed 序列来解决。

先在独立输出、验证 AppId 与隔离配置中准备统一候选及兼容迁移。所有已签输入先固定，
新序列须高于对应已签 floor，同一序列只允许原字节重试。普通安装器保持原 AppId；
验证版保持独立身份。公网频道切换需在最终产物与恢复步骤可审查后执行，不用真实 feed 做测试。
资源包的大陆/海外分发和五分钟门禁仍按原记录分别判定，不能把本地启动或热缓存当冷下载成绩。

旧 Wallet28 的 engine-only 维护会绑定原 Game 的四份元数据；r10 又带不同引擎与更高 floor。
因此同一个五职业 feed 不能直接同时替两者换成统一 Game。统一安装器先随包提供新 Game 与引擎；
r10 使用该安装器升级。新统一 Game 的精确 VERSION 字节另绑定独立 `unified` 维护频道，
旧 Root、FiveClass 的精确 pin 和未知版本零网络发现规则保留。本轮不切换公网 feed，
不声称已完成两种旧版的统一自动迁移。
