# 七怪撤退：冷世界编排及真实 WebSocket 记录

本轮交付的是受限测试编排和两项有条件的网络结果，不是新的生产战斗修复或完整
P1 验收。法师、道士使用普通攻击后向空格撤退通过；战士仍未形成十四次有效
受击窗口。Windows 右键、施法撤退、持续奔跑/停手、全包围、存档恢复、配套
客户端发布和实际玩家验收继续开放。公开游戏仍为 R17，未切换用户安装或网关。

## 场景和边界

上一轮固定 R18 十项密集场景最多四个合格攻击者。其驱动在五个任意敌对怪附近
停止引怪，而固定 v6 资格检查需要七个存活 AI-0 CaveBat；原版直接追击遇阻不
选择侧移，原始刷新布局也不保证三格出口。本轮保留历史结果，不延长旧预算。

新增方法只存在于 simulation 的 `test-support`/单元测试构建，网关入口只在
`cfg(test)` 的显式忽略测试中。没有新增玩家命令、管理接口或生产网络权限。
独占 `127.0.0.1:0`，私有测试账号及恢复密钥通过进程标准输入/私有目录使用。

原始 D021 压缩地图 SHA256 为
`5e283984b31ee993c8d1157402f50d7e9d4984d8be92db49388c1e024e257ca2`；
解压地图为 `ef8d4d9499d64bc16161abebc2548a3c9a98e99a7f634205ba45a3532db44de3`。
两者曾被误当成同一种哈希，首次拒绝记录保留，原始地图没有改动。

测试把原始休眠刷新槽通过既有 materializer 激活：原先活跃 73 个，新增激活
78 个原有槽，总计 151 个（120 CaveBat、30 CaveMaggot、1 CaveBat0）。没有
新增刷新槽。随后一次性安排七只原有 CaveBat 在 `(59,56)` 周围，向上保留三格
出口；干扰、重叠或非法原始位置的环境怪被移到远处合法空格。每个位置差异都
在 `preparation.json` 中披露。原有 HP、属性、AI、朝向、时钟、掉落和完整重生
策略按字段投影保持相同，位置同时更新 native/object/packet/AOI，严格快照恢复
验证成功后才提交。这里是准备过的几何场景，不证明普通玩家自然引怪成功。

个人测试存档披露等级 30、原版三职业 HP/MP、金币 20000 和 D021 起点。账号注册、
人物创建、首次城镇绑定、登录、退出均走正常协议；没有注入装备或技能。最终
场景使用普通 EquipItem 装备原有 WoodenSword、BaseDress(M)、Candle。形成压力的
30 秒预算仍从首次 D021 StartGame 回包计时。正常配置的共享节拍是 **300 ms**，
没有改成较短的节拍；入场及初始装备后才启用自动节拍。

## 实际结果

最终 network-06 使用同一构建，每职业一个前瞻性试次，保持 v6 哈希
`f78103fb5ddb1516caac0f0b088bacd01421c5d9ede603a5c75a3c2b2c95dc0d`、
七个攻击者、滚动 6.2 秒内十四次正伤害、绝对 HP 下降和实时三格出口条件。

| 职业 | 资格 | 普通攻击后单步撤退 | 无移动输入观察 |
| --- | --- | --- | --- |
| 战士 | 未定：最多 0 次正伤害，未达十四次 | 未执行 | 未执行 |
| 法师 | 七怪、十四次正伤害合格 | 531 ms ACK；等待期间收到真实伤害；通过 | 五秒以上，无漂移，通过 |
| 道士 | 七怪、十四次正伤害合格 | 496 ms ACK；等待期间收到真实伤害；通过 | 五秒以上，无漂移，通过 |

真实攻击承诺、后续刷新资格、受击到移动 ACK 的闭合窗口及晚到/死亡记录都保留。
DamageIndicator 只有受害者 ID，不能把每一条伤害分配给某只怪。单步 ACK 上限仍
1500 ms，原版 550 ms 攻击、600 ms 施法动作和全局施法时钟没有缩短。网关测试
总耗时 142.85 秒，包括三职业建档、准备、普通连接和收尾；不是单次移动耗时。
三职业都收到普通 LogOutSuccess 并正常关 socket，玩家、zone session、live outbound
计数归零后，实际取消并等待测试监听任务结束。没有生产进程 SIGTERM 证明。

更早 network-05 是不同输入：未装备初始衣服，战士最多十二次正伤害仍未合格；
法师已合格，但被动等待下一次 ObjectAttack 超时，后续撤退没有执行，道士没有运行。
该失败不会被新结果覆盖。源码核对发现 StartGame 默认十五秒的个人周期刷新宽限，
ObjectAttack 也不在专用移动实时通道内。最终驱动在五秒攻击起手等待内继续正常刷新
快照，与形成压力阶段一致。没有改变服务器宽限或时钟。这不是受控装备/轮询
单变量性能比较，也不能据此认定生产的所有停手问题都已消失。

## 验证和剩余交付

字段；新增篡改 HP 时旧根必须拒绝的检查。原失败保留，最终 14 项全部通过。
默认 simulation/gateway 库编译检查通过；旧警告保持原样。没有修改生产快照验证。

证据见 [公开记录和哈希](generated/player-qa/classic-cold-fixture-20261006/README.md)。

测试节拍注释作非语义整理，新增冷恢复断言单独通过。不能把这套 Windows 测试
EXE 当成固定 R18 Linux ELF 或客户端配套版本。

下一步保持 P1：解决战士正伤害资格场景，补施法/持续奔跑的闭合窗口和 Windows
输入、画面、保存恢复，然后生成配套候选版。P2/P3 等原定任务继续按队列推进。
`fullP1Accepted/nativeInputAccepted/nativeVisualAccepted/humanAccepted/`
`ordinaryProgressionAccepted/capacityAccepted` 全部为 false。
