# Formal13 本机资源采样观察

原正式容量未通过，本档只分析已结束的 2/10/25 人阶段。原游戏结论见[失败分析](../capacity-formal13-native-supply-failure-analysis-v1/README.md)。50/100 人、两小时长稳、保存恢复均未执行；P0=false，P2 未启动。

[有效分析](analysis-v2.json)和[独审收据](review-v2.json)对应 monitor 原始 544 行：542 个封装采样、各一个开始/停止记录。按实际阶段时间选择样本，百分位用 nearest rank；区间边界可能跨采样差分，峰值仅为已采样峰值。

| 阶段 | 样本 | 网关 CPU p95（逻辑核当量） | 网关 CPU 采样峰值 | 私有内存采样峰值（MiB） |
| --- | ---: | ---: | ---: | ---: |
| 2 人 | 153 | 0.079 | 0.110 | 547.6 |
| 10 人 | 152 | 0.359 | 0.573 | 1307.4 |
| 25 人 | 148 | 1.113 | 3.806 | 1871.8 |

网关与协议客户端共用 i9-13900KF / 64GB 本机；4 个 Tokio worker 与软停止线不等于云主机硬配额。主机逐逻辑核使用率还包含客户端和其它进程，不能归属为网关逐核使用率。短测内存仍在增长，未证明两小时平台或泄漏。

JSON 同时保留进程读/写/其它 IO 及主机 NIC 采样；进程 IO 包含文件/设备，不能当纯磁盘吞吐、同步延迟或容量。NIC 可能漏掉 loopback，也不只属于网关。整轮 WebSocket payload 是 1074.738 秒（含接入/扩容及三个阶段）的汇总，排除 WS/TLS framing；不能称为25人档公网带宽，更不证明带宽上限。

源脚本为[analyze-v2.mjs](analyze-v2.mjs)，按原外部目录布局读结束档案，并用 wx 写新结果、不覆盖既有输出。原外部 monitor raw 仅引用字节数/SHA，不重复复制。独审已用独立统计复算每个阶段的所有标量。

首次 v1 未解封 monitor.sample，产生零采样无效结果；其[源码](history/analyze-v1.mjs)与[无效结果](history/analysis-v1-invalid.json)原字节保留，不能解释为资源使用为零。v2 修正解析并要求真实 start/stop 与每阶段至少100个有效样本；原游戏裁决保持失败。
