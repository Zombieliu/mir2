## Finding and scope

Normal shared monsters have no generic EXPOwner state. Their fatal damage chooses the final acting session; a protected first owner is not considered. Crystal retains an EXPOwner for five seconds after that owner's most recent effective damage. A rival's damage neither steals nor renews a live, unexpired owner. Separate shared drop protection currently turns the generated `60` ticks into `60 * 300 ms = 18,000 ms`; the original item Owner lock is one minute. Shared party awards also use an equal split across same-Zone members without the original 16-tile eligibility or level-weighted party bonus.

Those are separate changes. A bounded first writer should add ordinary EXPOwner arbitration and prove same-map behavior, then complete manager-owned online identity/lifecycle and cross-map delivery before claiming the whole Stage 3 gate. Item-lock duration and party formula need separate focused red/green rounds. Existing Boss contribution allocation is an explicitly retained product policy in the Goal ledger; the original generic Boss rule differs, and that difference must remain visible rather than being silently changed.

Do not change the user's daily/weekly counts or rewards (daily approximately five levels, weekly approximately ten levels), natural EXP tuning, or the periodic-quest claim journal to fix ownership.

## Death, teleport, logout, and checkpoint distinctions

`MapObject.cs:339-375` shows Node is an entry in global Envir.Objects, not an entry in one map. `MapObject.Teleport:780-800` removes/re-adds the map object and changes CurrentMap without removing Node. Therefore an ordinary online map transfer does not, by itself, release EXPOwner or ground Owner. Logout runs PlayerObject.StopGame/Despawn (`PlayerObject.cs:266,405`) and does remove Node, after which other objects clear refs in Process. Death also keeps the global object Node. A ground Owner remains protected if its owner dies; it clears after timeout or actual despawn. A revive of the same spawned object is not a new login identity.

This makes a simple `zone.leave => clear all ownership` incorrect: shared manager currently uses the same Leave path for map transfer and actual departure (`zone/manager.rs:432-496`; `zone/runtime.rs:2484-2535`). The transfer path already knows `online_map_transfer` and preserves receipt/action/status clocks. Ownership needs a trusted, single-writer manager identity boundary with separate transfer vs actual despawn events. Preserve the same spawned connection identity through teleport/death/revive; do not validate an EXP claim only with the combat life_generation, which intentionally changes on death. Use stable account + character + spawned/connection epoch, authenticated session/object references, and monster incarnation to prevent ID reuse/ABA.

The old Zone still needs to resolve an owner now online in another Zone for death attribution, drop bonuses, current group context, and reward delivery. Do not keep a duplicate authoritative player world inside a personal SimulationSession, and do not substitute an offline account login for a still-alive EXPOwner reference. On actual logout/despawn, revoke the online reference in every retained Zone; already-produced immutable kill receipts remain deliverable exactly once to their captured account/character.

Checkpoint is a different operation again. Crystal has no persisted EXPOwner/LastHitter in CharacterInfo: these are transient spawned-object references. The Rust Zone checkpoint already serializes live monsters, players, pending hits, and drops (`zone/runtime/checkpoint.rs:181-208,621-656,733-753`). A same-epoch deterministic checkpoint should retain the remaining deadline without refreshing it and authenticate its owner/ref/expiry. A real process restart must not resurrect an online Gateway session (`zone/manager.rs:336-340`); transient owners must be detached/invalid unless the same trusted online epoch is deliberately recovered. Already-delivered or pending account receipts are not reset. New optional fields need neutral legacy defaults and canonical state-root coverage; versions 1-3 clear unauthenticated forward fields before use (`checkpoint.rs:740-744`). Do not make a legacy injected owner/deadline trusted merely by adding serde(default).

## Proposed one-writer implementation sequence

1. **Red same-map tests first** in a new external `apps/simulation/tests/shared_monster_ownership.rs`. Use real synchronous Zone commands for joined players, server-authored ordinary spawn, PlayerAttack/PlayerMagic, and advancing Tick. Do not inject private monster owner fields or manufacture a production admin packet. A fixed hp/exp/drop spawn is a fixture-only source, not proof of normal network spawning.
2. **One runtime writer** owns `zone/types.rs`, narrow edits to `zone/runtime.rs`, and preferably a new `zone/runtime/experience_ownership.rs`. Add an optional authenticated owner reference/deadline on monsters, establish/renew ordinary direct player/pet ownership only after positive applied damage, expire at source strict >, and preserve the source periodic poison and TurnUndead exceptions above. Pass source actor kind/pet object into effective damage arbitration rather than blindly trusting a normalized session. At ordinary death use retained EXPOwner for EXP, quest credit, drop bonuses and ground owner, even if the final damage itself had no player session. An unowned wild hit does not itself claim or necessarily erase a previous valid owner; retain the explicit source AI 6/58/113 clearing behavior. No retained owner means no EXP/drop; remove direct/thunder/vampire fatal-actor fallbacks. Suppress wild-monster rewards for targets with a Master. Preserve Boss and special AI policy until their focused review. Spawn/respawn clears the new claim; checkpoint new state cannot refresh a claim or bypass root authentication.
3. **Manager lifecycle completion**, same writer or a separate round with explicit ownership: `zone/manager.rs`, narrowly owned checkpoint identity handling, and root-owned Gateway routing tests. Distinguish online transfer from actual despawn, maintain world-owned trusted owner refs across Zones, and route cross-map death awards to the authenticated original account/character without fabricating a local player. Source damage eligibility uses actual current pet/master positions. Test logout/rejoin and same-ID different identity independently from same-object death/revive/teleport. Only after these tests pass is generic ownership Candidate beyond the same-map slice.
4. **Drop-lock round** owns `runtime/drops.rs`, narrow Zone expiry/pickup and Gateway countdown conversion. Use explicit canonical milliseconds or a named conversion that makes minute protection exactly 60,000 ms; leave the 300-ms world tick alone. Do not blanket convert custom fixture tick windows. Preserve owner/group access and canonical ground generation/item identity while fixing online-transfer and actual-despawn owner release.
5. **Party/Boss policy round** owns the award splitter and authenticated world group context. Match source level/range/bonus/truncation, including deciding how literal source denominator quirks are represented. Keep chosen loot owner separate from party EXP recipients. The existing custom Boss policy must be explicitly retained or explicitly approved for a source-parity profile; no silent switch. Verify adjacent configured NoExperience/NoDrop and over-level EXP behavior without changing periodic task rewards.

The root coordinator owns integration/docs and normal Gateway acceptance. No further runtime writer should edit these high-conflict files concurrently. The plan proposes these scopes; it is not authorization to edit them.

## Regression matrix and acceptance limits

Each test must assert real outbound recipient, amount, HP effects, drop owner and item identity, not just an internal field. Use impact time and legal cadence; after source timeout, run the equivalent Process/Tick before impact. Predicted failures below come from source inspection, not a test run.
