## Warehouse transfer contract recheck

Crystal MirItemCell routes an empty target through StoreItem/TakeBackItem,
a compatible non-full target through MergeItem with both unique IDs, and an
incompatible occupied target to the first free destination. It does not swap
items across bag/storage. A storage-to-storage move may swap; equipment-to-storage
is another source path and must remain a separate acceptance item.

Native simulation StoreItem/TakeBackItem rejects occupied targets. MergeItem
supports both bag/storage directions and enforces active storage service,
password lock and accessible storage size. Its bag indices exclude the belt;
Crystal's fallback starting at index 6 corresponds to native bag index 0.
The targeted simulation command `cargo +1.95.0 test -p mir2-simulation --lib
--offline storage` passed 59 tests, 0 failed. Receipt:
`C:/mir2-ui-repair-20260921/storage-backend-contract-tests.log`.
The separately named `store_and_take_back_reject_occupied_targets_like_crystal`
test also passed 1/1 (`storage-occupied-target-tests.log` in that directory);
the `storage` name filter does not include this test.
This supports the backend contract, not the uncompleted native pointer path
or visual acceptance. Actual concurrent bag and target-cell drag are in progress.

Font ownership source audit: no repeated project-created font handles or dynamic family/size construction was found. Arial and Microsoft YaHei use fixed pixel sizes. An upstream cache eviction/reload can assign a fresh font Blob ID and hence a new atlas key after unused-frame gaps, but the native runtime cadence has not established this mechanism. The staged ownership telemetry must distinguish font atlas growth from other image paths; this remains a hypothesis, not a memory fix or stability pass.
