# 当前 Windows 资源全量核对 — 2026-09-21

## 结论

当前资源包不能称为所有怪物和物品显示完整。核对覆盖完整导入目录，
并单列当前 platinum_176 白名单、实际刷新引用、新手任务和装备外观。
本轮是静态资源/映射审计，没有运行角色、修改存档或作视觉通过声明。

| 核对范围 | 结果 |
|---|---|
| 完整怪物目录 | 555定义、296条当前服务端库路径，覆盖6341刷新记录 |
| 当前白名单怪物 | 174定义中164不满足当前native动作帧可达性 |
| V2目标与BoneFamiliar | 11种中9种缺帧或缺native渲染资源路径 |
| 全部物品背包/商店图标 | 1628目录行引用924帧，均匹配原版可见像素 |
| 装备面板纸娃娃 | 421目录行引用214帧，均匹配原版像素 |
| 地面掉落 | 928帧含金币，33帧原版透明，1帧原版零宽且导出PNG不可解码；涉及102目录行 |
| 当前195项物品白名单 | 图标和地面帧无上述资源缺陷 |
| 当前武器/衣服地图外观 | 54件中49件缺直接资源库；其余5件仅最低库存在性通过 |

## 原因

怪物不能仅检查 PNG 文件存在：native 的独立 PNG 回退允许人物、坐骑、
宠物和地面物品，但不允许 Monster 库，未进入图集的怪物仍无法生成身体层。
Oma/ForestYeti/Skeleton/Zombie2/Zombie3 仅导出部分帧；
Dung/WoomaSoldier/WoomaFighter/BoneFamiliar 缺整库。
ArcherGuard 部分帧有图集，但完整动作仍缺帧。

此外，服务端当前统一 Monster/{image} 的映射不能完整表达原版 Gate、
Dragon、Pet 特殊库。报告中的缺路径不能一律解释为原版素材不存在。

Items、StateItem 与人物地图上的 CArmour/CWeapon 等库是不同资源。
历史外部 QA 包曾补过部分装备库，但当前仓库 public 中并没有这些库，
所以旧包的结果不能套用到新包。两个最新本地测试包的 mir2-assets
junction 都指向本次检查的 apps/web/public；未核对运行进程的环境覆盖。

## 修复顺序

1. 优先新手路线9种缺漏怪物和Bichon缺漏，补原版完整动作并接入native路径。
2. 补当前白名单49件武器/衣服所需库，核对性别、职业、等级变体映射。
3. 修正Gate/Dragon/Pet特殊映射，扩至当前白名单其余怪物。
4. 明确34个原版地面空帧的产品策略；不拿其他物品图冒充原版，也不将其
   计作漏导出。修正零宽PNG导出行为需保留空源语义。
5. 用自动资源门禁防止回退，再对仍不确定的动作、穿戴、遮挡、位置做实机验证。

本轮未批量改动业务代码或资源；审计发现的全量缺口仍待修复。
先前HookingCat和背包移动修复包已独立完成，待正常退出后切换。
